# 模型定价重设计接口契约

实施基线：PR #29。沿用现价、权限、官方任务绑定、完整矩阵发布与任务快照。

## 共享只读价格描述

公开 `/api/pricing` 各 models 行、管理 `/api/admin/pricing-catalog` 各 models 行新增 `pricing`（兼容旧字段）。

```ts
interface PricingDescriptor {
  billing_kind: 'token'|'image'|'per_call'|'audio'|'mixed'|'video'|'generic_video'|'unknown'
  currency: 'USD'
  unit: string
  status: 'published'|'partial'|'missing'|'blocked'|'disabled'
  rates: { key: string; amount: string; unit: string }[]
  combinations: { key: string; mode: string; resolution: string; input_video: boolean; service_tier: string; draft: boolean; amount: string }[]
  endpoints: string[]
}
```

金额是十进制字符串。rates.key 沿用通用字段名；unit 采用 `USD/1M_tokens`、`USD/image`、`USD/call`、`USD/1K_characters`、`USD/1M_audio_tokens`、`USD/1M_video_tokens` 或 `mixed`/`unknown`。combinations.key 使用现有 priceCellKey。视频只列有效已发布组合，不将官方候选放入可售数据。公开响应不允许成本、作用域、内部渠道/上游名称、证据及冻结参数。公开模型返回规范对外身份，与能力/创建接口一致；第三方适配器不自动套用 Ark 公式。

管理行保留 key/provider/channel_id/model/upstream_model/pricing_kind 等字段；pricing 状态结合实际渠道/绑定/能力/有效规则，不能单靠价格非零推断可售。新增摘要必须批量读取，避免每行请求。

## Seedance 准备、校验与发布

新增 `POST /api/admin/video/models/:model/pricing/prepare`，要求当前有效 superadmin。请求：`{expected_config_version, channel_id, cells}`；cells 为完整编辑矩阵。服务端检查绑定及基线版本，并保留旧规则中非默认维度。响应：`{request, diff, sources}`。

`request` 为现有 pricingRequest 兼容扩展后的完整请求（建议新 config_version/pricing_version、expected_config_version、cells，以及与旧 evidence_hash 区分的类型化来源信息）；前端将 request 原样交给 validate/publications，不自行构造来源摘要。

`diff` 为 `{key, change: 'added'|'changed'|'unchanged'|'disabled', before: PriceCell|null, after: PriceCell|null}[]`，完整覆盖所有保留/变更/停用项。`sources` 是仅管理员可见的来源说明；前端只读呈现，不参与真实性判定。来源信息具体结构由后端实现后补充本文并通知集成。

prepare 不发布、不修改正式规则、无上游调用；唯一版本与并发最终仍由发布事务兜底。来源必须引用现有可信目录或现行来源，官方原文件 hash、来源集合 hash、body hash 分开；来源存在不代表能力或最低量已核验。新来源信息保存在版本快照中；避免新增不必要的价格表。

前端任意字段改动、切换模型/渠道/组织使 prepare/validate 结果失效。修改现有组合只改选定字段，隐藏行原样保留。禁用某组合必须在 diff 中明确显示。普通最低量登记仍需要显式人工核验，不自动登记。

## 组件边界

- 后台目录负责 AdminPricingPanel、通用表单与 PricingDrawer 包装；继续嵌入 VideoPricing，传入 selectedModel/selectedChannelId/contextKey。URL 前缀 `pricing_` 与外部后台标签参数分开。
- VideoPricing 负责内部四页签、简化矩阵、批量售价、prepare→validate→publish、完整快照及未发布修改提示。通过 `dirty-change` 告知包装层，暴露关闭/丢弃协作接口需与目录开发者明确一致。
- 公开目录共用新的模型目录组件，复用 PricingDescriptor；公开与管理端只共享展示类型，不共享敏感响应。
- i18n 分别使用独立模块文件，最终由集成角色挂入 9 个语言字典，避免并发修改。
