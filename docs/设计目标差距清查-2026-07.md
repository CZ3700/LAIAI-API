## 二、P1 —— 设计承诺的产品能力，商用前该补

- **Notify 统一通知层（§4.9）**：现状散装四成——验证码邮件✅（但 handler 内同步发）、运维飞书告警✅（fire-and-forget 无重试）；缺：**用户级余额预警/用量告警邮件、租户 webhook、统一通知抽象（事件→通道路由+重试）**。SMTP 基建可复用，是 §5 usage alert 的载体。
- **budgets 与 per-key 限流**：per-key scope 字段有名无实（不校验）；无 key 级 RPM（现为 org×model 全局单值）；无 member 级消费预算（entitlements 只有成员数上限）。指令 §5 验收"按 org/member/key 控预算"未达。
- **发票/开票**：零实现（企业客户刚需时新排期）。订阅/套餐为**有意不做**（预付费+按量），但 roadmap C2/设计 §4.6 M4 仍写着订阅——见 §五文档债。
- **OpenAPI spec + 开发者文档站**：spec 文件不存在，"API Reference 从 spec 生成"无从谈起；docs 站（VitePress SSG）未搭，现由 web SPA 的 Docs.vue 页过渡。设计定位"文档即产品、全球开发者第一触点"。
- **可观测最小集**：OTel/Prometheus/Sentry/Grafana/Loki 整条外部栈为零（应用内自建的状态页/渠道健康看板/资金告警质量高）。最小补法：/metrics 端点（relay 黄金指标：TTFT/上游错误率/hold-capture 偏差）+ Sentry panic 上报 + 日志脱敏 Handler（现靠写入点纪律，新代码漏写即泄）。
