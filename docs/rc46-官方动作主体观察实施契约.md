2026-10-27，主控已批准合并实施 A3 + A4-min。独立工作树 `D:/workspace/laiai/.cache/rc46-official-action-membership`，分支 `codex/rc46-official-action-membership`，基线 main `72d46780b344a6fd6fd4c50b8d806067cf378900`（与 PR76 head d0506e7 tree 相同）。本契约及整体架构先于业务代码落盘；范围及以下 A/C 接口已获主控最终批准，当前正在实施，尚无真实 MySQL 或部署通过声明。

## 1. 已批准目标与真实消费者

本批将一次 callerTx 的有限成员/主体观察接入现有 **legacy Catalog / ReadCatalogTx、EstimateForKey 和 Create 的新受理分支**，不再交付只有测试调用的组合模块。grouped 的解析组合可做真实 MySQL 内部验收，但签发、VerifyKey 和生产受理继续拒绝，不能声称分组受理或全入口授权已完成。

当前实际改善：EstimateForKey 原来仅将调用方 Key 放入资源 context 后调用 plan；Create 的 FeatureVideo/scope 主要由 HTTP 校验。新服务边界以当前事务内读取的主体、模型限制和 scope 为依据，覆盖直接领域调用以及认证后、caller 事务首一致读前已提交的变化。官方目录已有主体三读和动作规则，本批复用并接入同一组合逻辑；价格、能力、固定 Channel、Quote/Reserve 与原资金顺序不变。

“当前事务”不是 current-read 许可。“首一致读”一律指 **caller 事务建立 RR 快照的第一次一致读**，它可能是 idempotency 查询或其他业务查询，不必是 subject 第一条 SELECT。主体 reader 不重置快照、不另开事务、不升级锁；相关并发测试必须围绕该真实边界安排，不得把晚于 idem 快照但早于 subject 的撤权当作必定可见。

## 2. 本批边界

交付：opaque 成员观察、现有 A1 有限规则复用、官方三个动作的纯组合、当前实际目录与两个服务入口接线、真实 SQL/HTTP/资金回归。

不交付：grouped Key 签发/VerifyKey 开放、通用 Relay/Task 新授权、重试选路/worker 最终许可、撤权线性化、授权受理记录、策略版本 DDL、视频 BYOK、价格算法调整、历史 POST 新重放政策。收到的回执、GET、delivery、cancel/delete、独立恢复与结算保持原入口。

本批只有同事务观察，不是可复用发送许可。RR 下 caller 首一致读后的撤权可能不在本事务可见；不将其声称为最终 current-read fence。Key/Group/Grant 三版本仍不覆盖 Channel.Models、Org 功能、能力和价格变更。

### 3.1 通用动作事实的现有上限

- 实际 RelayMode 为 chat、embeddings、rerank、images_generations、images_edits、images_variations、audio_speech、audio_transcriptions、audio_translations（relay/mode.go:27–39）。Realtime 与 Task/MJ 不在该枚举。
- modeUpstreamSpec/formatModeSpec 是真实上游端点和鉴权矩阵；不是“这个具体模型支持此动作”的事实表。
- SupportsCatalogMode 注释明确只用于文档 transport，且 ModeChat 分支宽泛返回 true（relay/catalog_mode.go:3–17）。
- genericDescriptor.Endpoints 是说明链接；tokenGuideEndpoint 依赖 ModelMeta.Category，但注释明确 metadata 不参与 routing/classification/price（pricing_descriptor.go:48–73）。一个全局 ModelPrice 还可能同时有 token/image/audio 价，不能推成模型的完整动作能力。

因此本片不得把这些字段改名为 AllowedActions。通用 preview 后续只能分别标出 `group_membership`、`transport_supported`、`pricing_present`、`model_capability_not_verified`；在缺事实时不得将三者合成“可发送”。本片通用 `/v1/models` 保持已有三读与展示语义，不重新设计其价目，也不借此新收紧全部平台模型数量。

## 4. A/C 最小接口与单次读取

以下为 A/C 已对齐并获主控批准的实施接口；实现与验收状态见本契约记录。公开输入只包含可信身份引用和业务 model/action；不得接受请求提供的 mode/group/subset/version 来替代数据库事实。

### 4.1 routinggroup：一次有限成员观察

```go
// 字段私有，零值的所有读取/判断均失败关闭；不实现 JSON 序列化。
type MembershipObservation struct { /* validated subject/group/grant/channels */ }

func (r *CandidateResolver) ReadMembershipTx(
    ctx context.Context, tx *gorm.DB, ref CandidateSubjectRef, at time.Time,
) (MembershipObservation, error)

type ModelMembership struct {
    Mode string                 // legacy / inherit_group / subset
    Model string
    ModelIncluded bool          // 名称规则；不是动作授权
    ChannelIDs []uint64          // grouped 精确绑定；legacy 非nil空，不能理解成全渠道
}
func (o MembershipObservation) ResolveModel(model string) (ModelMembership, error)
func (o MembershipObservation) ContextFacts() (CandidateContextFacts, error)
func (o MembershipObservation) Observation() (CandidateObservation, error)
```

合法 legacy 在新 ReadMembershipTx 中是显式分支：校验真实 Subject、无 RoutingGroupID、版本非零，保存原 LegacyModelAllowed 语义，不读默认组、不枚举全站渠道。ResolveModel 先校验 observation 有效性；legacy 分支直接沿用原 LegacyModelAllowed 谓词，不增加 grouped 的模型名格式检查或模型集合限制，避免收紧已有未知/损坏 cfg 的安全诊断路径。`ModelIncluded` 为原精确白名单结果；具体 Channel 的发布/归属继续由消费域判断。grouped 复用原 group/grant/bindings/channels 全规则与上界，ResolveModel 继续严格校验模型格式，ModelIncluded 仅在精确可用 ChannelIDs 非空时为真。未知 mode/损坏事实不回退 legacy。

原 A1 ResolveModelCandidatesTx/ListModelCandidatesTx 签名和 ErrCandidatesLegacyMode 语义保持，内部共用 subject/group/grant/channel 有限读取和纯集合规则。特别保留原边界：原 List 的总模型集合超过1000会拒绝，但原单模型 Resolve 在同样超过1000的集合仍可解析目标；不得让旧单模型入口委托新的完整枚举而改变该行为。新 MembershipObservation 对 grouped 完整集合设1000上界；官方目录对至多四个模型调用 ResolveModel 只是纯 CPU 操作，禁止循环调用四次 Tx resolver，也不另造目录分页算法。

Observation()：legacy 的 Assurance 固定 `legacy_model_membership`，GroupID/GroupPolicyVersion/GrantVersion 为0；grouped 保留 `group_membership_only` 及真实三项版本。两种都不表示动作授权。ContextFacts() 返回原白名单字段的值拷贝；ChannelIDs 每次返回独立副本，非nil空集合不表示所有渠道。构造时也复制 reader 返回的 RoutingGroupID 指针及 channels.Models 切片，避免 bridge 持有别名后修改 opaque 事实。新 grouped 观察只在一次读取后构建有界私有模型映射，多个 ResolveModel 不再 SQL 或重复解析。零值 observation 的三个方法都返回 ErrCandidatesInvalid，不能默认为不限模型。

为保持唯一 legacy 纯语义，主控已批准 A 的必要最小文件扩展：将现 identity.LegacyModelAllowed 的纯函数体原样移到 routinggroup/membership_rules.go 的同名导出函数，identity/video_catalog_access.go 原同名函数仅委托；原 AllowsModel、签发和 VerifyKey 调用行为不变。identity 已依赖 routinggroup，禁止反向 import 形成循环；不新增 matcher 回调或公共宿主包。

观察有效期仅为本次调用栈和 callerTx；不可缓存、不可作为授权受理凭据、不可跨事务传给 Create/worker。对外仍输出现有安全 DTO，不输出 raw KeyScopes、model limits、ChannelIDs 或内部组版本。

## 5. 实际调用顺序与回滚边界

### 官方目录 / SDK discovery

现 Catalog 或 listPricedModels 的主库只读 RR/共同 1s 保持。ReadCatalogTx 以新的单次成员观察替代原 identity subject 三读（不是在旧三读前再叠三读）；然后原 configs/scopes/Policy/channel/tariff/ratio/assets 有限批量读取，纯组合模型及动作。SDK 通用段仍在同一事务追加原三读；Commit 成功且 parent ctx 有效后一次性输出。零模型的合法结果与读取失败仍区分。

### EstimateForKey

在现有服务事务内只用 key.OrgID/key.ID 作为引用，先重新读取主体与 model/scope；不可把传入 key.Scopes/ModelLimits 当权威。通过后调用原 plan 并按当前请求 cell 的已有发布规则完成报价，返回原 QuoteResult。目录完整 tariff snapshot 不得在 plan 前额外读一遍。Estimate 不因 FeatureVideo/Policy 关闭或无执行凭据而被新增拦截；保留原动作分离。

### Create（只改新受理分支）

保留现有 HTTP 和服务前置模型检查，以及 idempotency 冲突/重放顺序。本片**不落实**已批准待后续的“模型撤权后历史同 body 仍可回执”新策略：现同 body 重放继续原行为，不在旧重放分支新增能力/价格/Policy/组检查。

仅 `claimIdempotencyTx` 判断非 repeat 后，在原事务读取一次当前主体/成员/Org、model、video:write、FeatureVideo；原 Policy 读取复用，随后原 plan/固定 Channel 锁读/凭据选择/Reserve/Stage/Task/Operation 写入顺序保持。新检查须在凭据快照/Reserve/Stage 前完成；失败时本次新 idempotency 行同事务回滚，不留下未完成受理。

调用方 Key 只作身份引用不作授权事实，成功后不得用新观察重建历史 price/scope/input HMAC。实际 SelectCredential 仍为 Create 的唯一凭据选择，目录 `HasUsableCredential` 不是解密成功承诺。

原 `Estimate(org, in)` 当前只有测试/内部兼容调用，生产 HTTP 只走 EstimateForKey（rg 核查）。本片应保留原受信任内部语义或按调用点明确弃用，不伪造 KeyID=0/无限白名单来接新 helper；不可将它注册成绕过 Key 的新公开入口。

成员观察沿原100 binding（第101整体拒绝）、每channel原Models≤64KiB、总原文≤1MiB语义门槛、模型集合≤1000、单名≤128字/512字节；它不是全平台 legacy catalog 的新截断规则。官方仍最多4 canonical，cfg读取原LIMIT65、价目/最低覆盖全量上界与算法原样。

成员观察总期限≤1s、每 SQL≤200ms且不超过 caller 剩余；读取后先查 child ctx，再 cancel；CPU解析继续用共同 parent。目录同一1s不因增加逻辑延长。Create/Estimate 保留原 caller 业务事务期限，新增有限读取共享该 caller 剩余，不另开RR/不另取连接，不能给每个模型重置1s。

实际 MySQL 测法：

1. 在真实事务记录 Query/Row/Raw 的 SELECT 执行及 ConnPool/CONNECTION_ID，不能只数一种 GORM callback 后声称完整预算；记录 SQL结构和占位数量，敏感值不输出。count 包含真实扫描完成，拒绝悄悄用 Raw 绕计数。
2. 完整四官方模型 fixture 与至少一个通用模型的生产 HTTP 路由断言15/18；同时单独统计分域查询，禁止总数碰巧相等却重读主体/漏读事实。
3. 成员观察 grouped 单模型与4模型纯 Resolve 在同一 tx 内仍最多7；100/101 binding、1000/1001模型、1MiB边界复用 A1 原 oracle，不靠页面截断隐藏超限。
4. 每个reader阶段实际1054、取消、child200ms超时、parent超时，要求零值/安全错误，不能 partial/空集合成功。带污染的 caller Where/Select/Limit 仍同池清洁链。
5. RR 第二连接在 caller 事务第一次一致读（包括可能的 idem 查询）后变更主体/发布字段，本次观察保持同快照，下一请求反映变化；只读事务真实写入1792反例。写受理事务内读必须看见本事务未提交事实，结束由原caller决定commit/rollback。
6. 新建受理的当前主体变化在 **caller 事务的首次一致读前**置入（包括可能先执行的 idem 查询），要求拒绝且 Reserve/Stage/Task/Operation/凭据快照/新idem均无残留；caller 首一致读之后的撤权不在本批承诺范围，不能写一个假 current-read 断言。
