# 模型目录与简化定价模块实施方案

日期：2026-10-19。状态：已实施并通过本地验收，阶段分支与集成分支提交评审，未合并生产。实施基线为 `codex/maas-pricing-provider-alignment`，提交 `20b269dc63f77c925a4fed61c852b9bc01840859`（PR #29，实施时仍未合并）。现有运行价格、发布状态和账务数据核对不变。最终实现与验证记录见[验收记录](模型定价重设计验收-2026-10-19.md)。下文保留原方案，实际交付边界以验收记录为准。

建议统一为“模型目录 → 右侧定价抽屉 → 预览变更 → 发布”的操作路径。模型目录承担发现、筛选和对比；抽屉默认展示运营需要填写的售价，把官方来源、最低 Token、冻结参数和版本记录放入二级页签。客户模型页与后台共享模型身份和计价描述，但返回不同权限的数据。

## 1. 参考依据与本次范围

[TokenHub 模型广场](https://ai-tokenhub.ai/zh/models)的公开页面提供模型搜索、币种、供应商、计费类型、标签和端点筛选，并说明模型价格卡片可查看基本信息、API 端点与价格详情。本方案借鉴这套信息组织方式；下述抽屉、编辑流程和接口设计是针对 LAIAI 的建议，不代表已核实参考站后台实现。

方案阶段浏览器连接超时，未完成参考页动态详情审查。实施阶段已补录 TokenHub 公开模型目录截图及本地新目录、桌面/窄屏抽屉截图；参考页动态详情与后台实现仍未作为已核实依据。

| 核对步骤 | 当前情况 | 结论 |
|---|---|---|
| 1. 参考模型目录 | 公开筛选结构可读取，动态卡片及详情未完成截图核验 | 借鉴目录结构，具体视觉在实施前复核 |
| 2. 本地后台定价 | 代码已具备厂商、渠道、真实模型和计价类别投影；长页面同时展示成本、矩阵、最低量及版本表单 | 数据来源可复用，需要重组操作路径 |
| 3. 本地公开模型页 | `/api/pricing` 主要读取通用 ModelPrice；卡片统一展示输入/输出/图片三列 | 必须补充视频价格投影，单换卡片样式无法解决 |
| 4. 发布与账务 | 视频发布替换完整价格版本，任务保存创建时快照，实际 usage 与冻结估算分离 | 简化 UI 必须保留完整矩阵、并发校验和历史快照 |

本次实施范围建议包括 `/models`、`/app/models`、管理后台“定价”及旧“视频定价”入口。请求日志、素材库继续使用已有功能，仅补相关深链接和计价说明，不在本轮重做这些模块。

## 2. 模型目录与后台使用同一套信息结构

页面顶部保留搜索、模型类型和卡片/列表切换；左侧为可折叠筛选区。主要类型为文本、图片、视频；已有 Embedding、音频等能力按真实类型保留在扩展筛选中，不能为了三类展示误分类或删除既有模型。文档站原定三个顶级分类不随本轮变更。

| 区域 | 客户模型目录 | 后台定价目录 |
|---|---|---|
| 搜索 | 对外模型名、厂商、简介 | 对外模型名、上游映射名、厂商 |
| 筛选 | 厂商、类型、计价单位、标签、端点 | 同左，增加渠道和配置状态 |
| 厂商来源 | 真实可展示模型对应的厂商，标识沿用渠道注册表 | 完整 48 个注册厂商及已有自定义厂商，与渠道接入一致 |
| 卡片内容 | 模型名、厂商、类型、支持的输入/输出、实际价格单位、价格摘要、详情入口 | 同类信息，加接入渠道数、发布状态、待处理原因、配置入口 |
| 状态 | 仅把真正可调用组合显示为可售；无价不显示为 0 | 未接入、待定价、待核验、部分已发布、已发布、停用 |
| 币种 | 首版按真实结算币种 USD 展示 | 售价 USD，官方参考与内部成本基准 CNY，分别标识 |
| 操作 | 查看详情、复制对外模型名、查看文档 | 配置定价、预览客户页面、查看历史 |

默认卡片视图，批量管理时切换列表视图。卡片整块可进入详情，同时保留有文字的操作按钮；不依赖仅鼠标悬停、图标或颜色理解状态。搜索和筛选写入 URL，返回时保留滚动位置和选中条件。

客户目录不展示上游 Key、内部渠道名、账户 UID、ProviderScope、成本、冻结系数、内部证据或未发布组合。管理员看到的官方参考价与内部成本基准必须分清：公开参考价不必然等于账户合同成本，不能通过一次“同步参考价”静默覆盖已有成本。

首版不做币种切换。若之后增加 CNY 展示换算，必须显示“估算展示”、汇率时间与 USD 实际结算说明；切换展示币种不得修改价格或汇率快照。

## 3. 不同模型显示对应计价表单

分类和计价方式由适配器、价格配置与已验证能力决定；显示名称和营销标签不参与收费路由。不继续用名称包含 image/video 等关键词作为价格表单的权威依据。

| 实际计价方式 | 卡片价格摘要 | 抽屉主要编辑项 |
|---|---|---|
| 文本 Token | 输入、输出；缓存价按实际配置补充 | USD/百万输入 Token、输出 Token、缓存 Token |
| 图片按张 | 单张价格及适用尺寸/质量条件 | 已支持的张数计价字段；尺寸或质量只有引擎支持时才枚举 |
| 图片 Token 或按次 | 对应 Token 或调用单位 | 使用实际字段，不转换为虚构的按张价格 |
| Seedance 视频 Token | USD/百万视频计费 Token；按条件显示区间或起价 | 分辨率 × 有/无参考视频的售价 |
| 其他视频按秒/任务 | 按当前适配器真实单位显示 | 只开放引擎已经支持的维度；未支持明确待接入 |
| 混合/音频/其他 | 保留各实际单位，不跨单位比较起价 | 复用已有字段，未知模式提示待识别 |

“起价”只能从同币种、同单位、同任务口径的已发布可售组合中计算，并附条件；不能把每百万 Token 的单价写成每条视频或每秒。文本的输入/输出价也不合并成没有含义的最低单价。

对外模型名是调用身份，渠道厂商 ID 是接入身份，品牌 vendor 是展示信息。三者分开。通用价格仍按公开模型名跨渠道共享，编辑前显示影响范围；官方视频仍绑定明确渠道和账户作用域。不能仅因展示名称相近合并 `doubao`、`volcengine`、`modelark`。

## 4. Seedance 日常定价只保留一个主表

进入路径：后台定价 → 火山方舟 → 视频 → Seedance 2.0 / 2.5 → 配置定价。点击模型、规则、记录等详情统一从右侧展开。首版优先完成标准 2.0/2.5；1.x 不进入配置，Fast/Mini 标注独立型号待单独接入，不套用标准版价格。

抽屉顶部固定显示模型、绑定渠道、计价单位、当前发布状态。主体首个页签为“售价设置”；底部固定“预览变更”和“发布”，中间内容独立滚动。1366×768 下建议宽度 880–960px，窄屏使用全宽抽屉；复用 `DetailDrawer` 的焦点约束、Esc、关闭后焦点恢复与 reduced-motion 行为。

主表结构如下。单元格内同时显示当前值/编辑值、发布状态和明确阻断原因，官方参考值以只读辅助信息展示。

| 分辨率 | 无参考视频售价（USD/百万 Token） | 有参考视频售价（USD/百万 Token） |
|---|---|---|
| 480p | 保留已配售价；缺失则显示待定价 | 保留已配售价；缺最低量则显示待核验 |
| 720p | 同上 | 同上 |
| 1080p | 同上 | 同上 |
| 其他官方参考组合 | 按模型实际目录补充，标记是否已核验 | 按模型实际目录补充，标记是否已核验 |

当前采集的标准生成、默认服务层级、非草稿候选共 14 组：2.0 为 480p/720p/1080p/4k × 有无参考视频，共 8 组；2.5 为 480p/720p/1080p × 有无参考视频，共 6 组。4k 等“已有参考价、能力未验证”的组合显示在“待核验组合”折叠区，不因为目录有价格就成为可售。任何已经发布的组合始终可见，不能因折叠默认项遗漏。

默认只查看当前可编辑或已配置的标准生成组合；“显示待核验组合”展开其他候选。草稿视频、编辑、延长、草稿转正及其他服务层级放在“其他任务模式”。这些仍是完整矩阵的一部分，不能删除或复用标准生成价格。界面用“未发布修改”表示编辑状态，避免与 Seedance 的“草稿视频”能力混淆。

运营常用操作只需要：选中模型 → 修改一个或多个售价 → 预览影响 → 发布。已有官方来源、最低量版本和冻结参数直接沿用。新组合若缺能力或最低量证据，在该格显示“缺什么”和“查看规则”，不会要求运营在主表输入 JSON、SHA-256 或版本字符串。

“批量填充”首版只对明确勾选的组合设置相同售价，或按明确的百分比调整当前售价；先展示逐格变更，不自动启用或发布。使用官方参考价换算并加价作为可选后续能力：必须显式选择汇率与加价率，生成 USD 候选后逐格预览。沿用此前决定，首版不启用“未定价自动按官方价格售卖”。

## 5. 复杂规则分到二级页签

| 页签 | 日常展示 | 管理行为 |
|---|---|---|
| 售价设置 | 精简矩阵、已发布/待定价/待核验状态 | 改售价、明确选行批量设置、预览与发布 |
| 计费规则 | 预冻结与结算说明、现用公式版本 | 查看冻结系数、汇率与支持范围；仅有权限者进入高级编辑 |
| 官方参考 | 参考成本、采集时间、来源、最低量覆盖摘要 | 查原始行；高级入口登记经人工核验的证据 |
| 发布记录 | 发布人、时间、变更前后价格及启停变化 | 查看右侧详情；恢复历史配置也须形成新版本、重新校验 |

来源与最低量不再整页展开。参考视频组合只有唯一、完整且已核验的匹配证据时才可自动关联；未知 FPS 保持未知，证据冲突时要求明确选择，不把目录采集或摘要校验当作人工认证。

默认展示“预冻结金额是暂时占用，最终计费根据官方实际返回的用量”。Seedance 不再显示无依据的“输入 Token 单价=0”；如果上游未分别提供输入用量，标明“未单独返回/不单列”，实际计费依据沿用 `completion_tokens`。参考视频是否参与输入是价格维度，不能用输入 Token 为 0 推断其免费。

预计费用只在已核验组合、明确分辨率/比例/时长等参数下生成，并标为估算；不可把普通帧尺寸估算当作官方实际用量。缺少估算依据时显示原因，不补假数。

## 6. 发布流程与数据安全边界

使用一个可理解的两步流程：“预览变更”打开抽屉内的变更摘要页，显示旧价/新价、启停变化、受影响模型和全部保留组合；校验通过后“发布”。任意编辑、切模型、切渠道或切组织使旧预览失效，不能拿旧校验发布新内容。

服务端生成不可复用的新价格/配置版本，前端显示只读版本。版本生成本身不占用业务资源，最终唯一性在发布事务中确认。`expected_config_version`、幂等键、请求摘要和审计继续保留。

证据摘要与提交内容摘要必须分开。官方原文件摘要、来源集合摘要、发布 body hash 表达不同对象，不能把一个 hash 当作另一个。建议新增受类型约束的来源引用集合：来源类型、模型/维度、目录版本、来源行和原文件摘要；由服务端解析已有可信目录并计算明确标注的集合摘要。变更来源信息要随发布快照保存；历史 `evidence_hash` 兼容读取，不能静默改变其含义。未绑定真实来源时，不因自动生成了摘要而标记“已核验”。

关键保留项：

- 发布是完整版本替换。抽屉必须持有完整矩阵，修改可见单元后合并隐藏行再提交；预览明确列出保留、修改、启用、停用。禁止仅提交当前页或当前筛选的行。
- 原 USD 售价、官方成本基准、启用状态、冻结系数、最低量版本保持现值，除非本次变更明确包含该字段。
- 没有有效售价组合时拒绝创建任务，不自动降级到官方价或免费。
- 计算金额仍按官方实际计费 Token × 创建时售价快照 × 有效倍率。现有首次实扣不超过冻结额、超额记录等行为保持，UI 不把计算金额和实扣金额混为一谈。
- 缺 usage 进入待用量状态，不用预估代替结算；历史任务不受后来改价影响。
- 本轮不修改 ledger、余额、原任务价格快照、官方接口路由、真实上游凭证或账单归属。

## 7. 最小接口与数据改造

以下为建议契约，尚未实现。

| 接口或组件 | 复用/新增 | 工作内容 |
|---|---|---|
| `GET /api/admin/pricing-catalog` | 扩展 | 批量投影售价摘要、计价单位、状态、已发布组合数量、阻断原因和影响范围，避免每张卡重复拉整张矩阵 |
| `GET /api/pricing` | 向后兼容扩展 | 追加类型化 `pricing`，读取已发布且符合调用条件的视频价格；保留旧通用字段兼容客户端 |
| 现有视频 pricing GET | 扩展 | 返回完整矩阵及可编辑字段、来源引用、逐格阻断原因；区分官方候选与现行规则 |
| `POST /api/admin/video/models/:model/pricing/prepare` | 建议新增 | 验证编辑上下文，生成建议版本、解析来源，返回完整待校验请求；不发布、不改余额、不调用上游 |
| 现有 `validate` / `publications` | 保留并增强 | 对完整矩阵校验和发布；增加可读 diff/影响范围，保持并发、幂等与事务语义 |
| 现有 `revisions` / `reference-candidates` / `minimum-rules` | 复用 | 放入对应二级页签与右侧详情，保持权限和人工核验要求 |

类型化价格描述建议包含 `billing_kind`、`currency`、`unit`、`status`、`dimensions`、`published_combinations`、`display_summary`。维度显式保留任务模式、分辨率、参考视频、草稿视频、服务层级；不要只用分辨率作唯一键。价格传输用十进制字符串；数据字段缺失与 0 分开表达。

公开模型和管理模型采用不同 DTO/查询投影。不能先取管理响应再由前端删除敏感字段。公开列表身份以对外可调用模型为准，模型目录、`/v1/models`、能力查询及创建接口必须针对同一模型对齐；上游别名不作为额外可售模型自动发布。详情中的 curl/Python/JS 例子复用本平台已实现的接口契约，尤其修复视频示例落到聊天端点等不匹配问题。

首版复用现有价格表、配置版本、发布快照与审计。不新增第二套计费引擎或平行价格表。编辑内容仅为会话内的“未发布修改”，关闭/切换/刷新前处理未保存提示；首版不承诺跨设备保存草稿。以后确需持久化草稿，再新增独立草稿表和顺序 migration，不将未校验草稿写入正式价格表。来源集合如需扩展持久结构，在阶段 0 锁定后走正式 migration，禁止 AutoMigrate。

权限保持：普通用户只读公开价；普通管理员按现有权限配置通用价格；官方成本、证据登记及视频发布仍要求有效 superadmin。编辑预览不扩大权限，展示隐藏不替代服务端鉴权。

建议使用 4 个并行角色：集成/审查主线 + 服务端 + 后台目录 + Seedance 表单。先锁定契约再并行，不同时改 `Admin.vue`、共享类型或 i18n 同一块；这些共享文件由集成角色负责。各分支单独提交、测试并发 PR，依赖 PR 在描述中写明，避免直接把多组未验收改动推入主分支。

旧 `/app/video-pricing` 入口先兼容导航至对应模型抽屉，保留原深链接含义；验证新旧同源之后再移除重复长表入口。回退只切换入口/前端版本，不回写价格或撤销账单。价格发布后的业务回退必须另建新版本并重新校验。

## 9. 验收清单

1. 后台厂商名称、ID、排序仍与渠道接入一致；无渠道厂商明确提示，不能生成虚构模型。
2. 文本、图片、视频按实际单位显示；空价不是 0，未知输入 Token 不显示为免费输入。
3. 官方标准候选 2.0 的 8 组、2.5 的 6 组及来源保留；1.x 排除，Fast/Mini 不使用标准价格。
4. 改 UI 前后，全部售价、成本、启用状态、冻结系数、最低量、配置/能力/汇率版本与账户余额保持基线。只读加载和 prepare/validate 不产生发布或上游任务。
5. 未发布/未核验组合不作为可售价格对外显示；条件不满足时发布按钮显示具体原因。
6. 切换分辨率、参考视频、模式、分页和批量编辑不会丢失完整矩阵中的其他行；仅改一格不会误停其他已发布组合。
7. 同名模型跨渠道的影响范围可见；绑定错配被拒；旧响应和旧校验无法污染新模型/组织上下文。
8. 并发旧版本发布返回冲突；重复提交不重复生成版本；公开页面在成功发布后显示新版本，失败时保持旧版本且不乐观显示新价。
9. 新任务用新价格，历史任务用创建快照；实际用量缺失、超冻结上限、取消/删除等原有账务边界保持。
10. 右侧抽屉在 1366×768、390×844 可操作，关闭和底部按钮可见；Tab/Shift-Tab、Esc、焦点恢复、错误定位可用；视觉审查不替代键盘和辅助技术验证。
11. 公共响应、页面源码和接口示例不泄露内部成本/账户/凭证；文档、模型名、端点与实际调用契约一致。
12. 各阶段执行相关回归；提交前 core/relay vet，推送前完整 `make ci`/`make ci-all` 等价门禁、前端上下文回归和 GitHub CI。需验证新价发布/结算时用隔离测试库与模拟上游，不动用户当前报价；本轮目录与 UI 验收不需要付费出片。
