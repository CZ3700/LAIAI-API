## 3. 资源与进程隔离

```text
唯一 runner 控制器
  ├─ 本轮私有 MySQL 8.4 容器（随机名、密码、拥有者标签、loopback 映射）
  │    └─ 每个场景独立 ark_test_action_<run>_<case> 数据库
  ├─ 独立 loopback mock Ark（按场景/target/instance/method 计数）
  ├─ C_a video.test
  ├─ P video.test，mutation=true
  └─ P video.test，mutation=false
```

- runner 不接受外部 DSN；拒绝继承 `LAIAI_DSN`、`ARK_TEST_MYSQL_DSN` 及真实模型凭据。为子进程构建白名单环境，移除外部 `LAIAI_*`/`ARK_TEST_*`、GOFLAGS/GOWORK/GOOS/GOARCH 等干扰，编译用 `GOENV=off GOTOOLCHAIN=local` 和仓库安全 Go 基线。
- DSN/合成 Key/数据密钥/HMAC 仅在私有环境传递，不作为命令行参数、日志或 run.json 字段。私有环境文件使用排他创建和 0600，结束时清除。
- 数据库名长度不超过 MySQL 上限，精确前缀+随机 run/case 摘要校验。每场景先 C_a 迁移，再 P 迁移，再 P 重放和 schema-doctor；不复用业务行、不通过清表/UPDATE 状态重置。
- 比较两边全部共同历史 migration 的文件 SHA，包括 0129；不能只检查 0127/0128/0130。P 独有文件以最终固定提交为准，本批自身无业务迁移。
- 测试 RoundTripper 先核验原请求确为固定官方 Ark HTTPS host/path/method，再改为本场景 loopback mock；底层 dial 仅允许确定 IP/port，拒绝其他 host、redirect、未知方法。保留真实 adapter Build/Parse/分类，不放宽生产 SSRF，不设置 AllowTestEndpoint。
- mock 独立于 worker，DELETE 计数先原子完成再发 READY，worker 崩溃不能丢计数。不得将认证头、请求正文、供应商任意错误打印到日志。
- worker 必须是 runner 直接启动并登记的真实 test binary PID。test2json 可接该进程 stdout，不应因包一层 shell/test2json 后把 wrapper PID 当 worker 杀。只向登记的本轮 PID 发信号。
- 清理先收完自有 worker/mock，再核对容器精确名称+run 标签，最后删除该容器及附属卷；不全局 prune、不碰其他数据库/进程。标签不符或清理失败均整体非 0。

## 4. harness 公共入口与控制协议

唯一入口建议 `TestMySQLMutationBinaryHandoffProcess`，要求显式本轮 runner 环境；普通 go test 可跳过，专用 runner 只接受实际 run/pass，任何 skip 失败。

可执行模式：

| 模式 | 允许行为 |
| --- | --- |
| seed | 合法基础组织、真实 IssueKey、Ledger.Post 入金、能力/价格/渠道/预算配置；使用公开 Create + ProcessOnce + mock POST/GET 建立任务、绑定和资金事实；公开 Cancel/Delete 创建意图 |
| worker | 接收 `run_once`、`advance_clock`、`release_barrier`、`stop`；仅通过 Service.ProcessOnce 执行业务，每进程至多一个活动周期 |
| inspect | 独立只读连接检查合成 org/task/op 的持久事实、计数和指纹；不修复、不应用、不解密正文 |

启动统一执行本版本真实 config.Load，然后 NewService、ConfigureResponseInbox，配置普通默认 create=false。P producer 角色须 mutation=true，P flagoff=false；C_a 新字段必须不存在。专门场景验证 create=true/mutation=true，不能通过在测试中直接赋值运行中开关制造组合。

harness 不调用 `registerMutationAttemptTx`、`prepareMutationResponse`、`appendResponseReceipt`、`applyMutationInbox` 或旧 fixture 的私有 helper，不裸插执行输入/attempt/receipt，不 UPDATE lease、due、status、HMAC、schema、应用进度。`Evidence.PurgeExpired` 是 R2 唯一允许的真实清理入口。

事件使用固定前缀加单行 JSON，例如 `A2C_EVENT {event,case,role,pid,sequence,...}`；字段只含固定枚举、合成 ID、摘要/计数/安全时间。runner 只接受当前 case/role/PID/sequence，拒绝未知事件和重复 READY。Go test 原始输出与 test2json 另存，事件不能冒充测试 PASS。

## 5. 真实故障屏障

主库和 response 专池各安装独立测试 ConnPoolBeginner/TxCommitter 装饰器，保留 GORM 所需接口。`Commit` 先执行真实 `sql.Tx.Commit()`；成功后独立第三连接确认目标事实，才 READY 并等待控制器。不得改变 Commit 返回结果，不采用“提交后伪造 EOF”作为本批 crash 屏障。

所有条件按精确 org+operation+kind 限定，不能触发到 seed 的 create/query。verifier 短 deadline，不通过被装饰连接或原事务验证。

| 屏障 | 独立连接必须已看到 | 后续允许 |
| --- | --- | --- |
| pending_intent | 公开 Cancel/Delete 已提交 pending；没有 mutation EA/response/DELETE | 正常退出 seed；任一版本可首次发送 |
| registered_before_http | P claim、schema2 输入 metadata/staging、EA 同事务提交；op=in_flight；response=0；DELETE=0 | SIGKILL P，禁止恢复者发送；租约到期后仅 unknown |
| delete_seen_no_response | mock DELETE=1，EA 已提交，response=0，mock 未给响应 | SIGKILL P，确认退出后断开等待连接；到期仅 unknown |
| inbox_durable_before_apply | 专池已提交 inbox、Invocation metadata、application.pending、response_received；op 未应用；DELETE=1 | SIGKILL P；等待/推进实际 lease 到期后由 first consumer 应用 |
| legacy_receipt_durable | C_a 主库 persistResponse 已提交 Operation.receipt_ref/outcome/status 与 Invocation/Attempt；receipt_applied_at=NULL；mutation EA=0 | SIGKILL C_a；P 可通过 legacy recovery 立即应用，不必等 lease |
| applied | 正常完整 ProcessOnce 结束，目标 receipt/app/Operation 状态满足动作语义 | 正常退出0；后继多次周期验证动作幂等 |

`legacy_receipt_durable` 已有现成挂点：C_a 的 worker.go:persistResponse 主库 Transaction 在函数返回 applyMutationReceipt 之前提交，无需新增生产 hook。

SIGKILL 阶段必须同时有：正确登记 PID、已核实的目标 DB 屏障、独立 mock 计数、实际退出信号 SIGKILL。此阶段记录 `expected_crash_verified`，不能要求或捏造 PASS。意外退出、屏障未到、仅 stdout 声称到达均失败。

## 6. 三种时间必须分开

### 应用逻辑时钟

每场景 T0 取实际启动附近的 UTC 时间并截为毫秒，所有进程开始一致。用 Service 现有 Now 注入；只能在周期空闲或明确屏障暂停时原子推进，不修改数据库 lease。

- seed 的首次 GET 会把 next_poll_at 推后10秒。需要再次真实 GET 时读取实际 next_poll_at，将各活动版本统一推进到它之后，再调用 ProcessOnce。
- N3/R1 已保存回执但 op 仍 in_flight：先在实际 lease 前运行 first consumer，断言不应用；再推进到 **持久化 LeaseUntil 之后**，要求真正应用。不能假定重启即可消费，也不能不看实际 lease 固定加4分钟。
- R2 推进到 **该动作输入 metadata.expires_at 之后**，同时确认越过 lease；精确调用 PurgeExpired 后再消费。

### MySQL 重试时钟

application.next_attempt_at 使用数据库 UTC，MySQL 恢复候选用 UTC_TIMESTAMP。推进 Service.Now 不能跳过此门槛。

Q1 cancelled-first 保留完整路径：C_a GET 先把任务与 cancel operation 确认为 cancelled/confirmed，P 随后真实收到原 ACK并保存；原 claim 失权，application.pending/claim_changed，next_attempt_at=DB UTC+30秒。控制器读取真实 due，有界等待 DB UTC 到达（默认40秒），再由 C_a 首次消费，然后 P flagoff 幂等检查。禁止 UPDATE due，也不改为 append 后杀 P来避开该分支。

### 强制墙钟 lease 门禁

至少 `N1-wall-cancel-Ca` 使用 Now=time.Now，不推进应用时钟。真实注册后杀 P，读取真实 LeaseUntil；租约前运行 C_a证明无接管，真实等待到期后运行 C_a证明 unknown。记录应用/DB时间、实际耗时，默认240秒阶段上限。不能把逻辑推进后等待几秒写成墙钟验证。

`${action}` 只取 cancel/delete；`${consumer}` 只取 Ca/Poff。每展开 ID 都是独立数据库，不能用前一个消费者处理后的 unknown/applied 状态充当另一个消费者的首次恢复。

## 8. 只读判定与独立 oracle

### 前置正控

- cancel任务必须已由实际POST得到官方绑定、当前queued，并有非零冻结hold；accepted的本地Cancel不合格。
- delete任务必须经真实GET succeeded+明确非零completion_tokens结算，并有真实扣费journal；Delete(cancelled)本地软删不合格。
- seed给出固定价格、汇率、风险系数、输入尺寸/时长、预期保留与用量，独立十进制计算最终金额，不用测试最终DB余额反推预期。

### 协议与动作

- 检查真实 org/operation/claim 唯一登记，action exact、schema2、purpose=execution、direction=effective_request、payload RequestID=OperationID、AttemptID真实匹配、完整四元组与固定ActionDescriptor/hash。
- C_a/P对同一动作的描述/hash一致，legacy v1 descriptor/hash不变。input/evidence HMAC版本非空且跨版本消费由实际业务验证，不在inspect手调apply补齐结果。
- 跨版本同一回执的 receiptID/payloadRef/evidenceHMAC保持；Invocation/application/response_received必须完整。legacy case禁止出现动作EA。
- delete仅合法终态软删；历史task/Invocation/回执/财务记录仍保留。
- 幂等事件只核对目标动作的应用事件、receiptID/applied_event_id；普通GET可能新增QueryReceipt/task.status_changed，不能要求全task事件表总数不变。

### R1/R2

- R1按准确response payload检查disabled与无staging，不只数整个org的staging。
- R2按准确 action input payload确认capture_status=expired、wrapped_key和nonce清空、staging删除；metadata中的org/op/attempt/schema/摘要/创建与到期时间保持。不能只用purge count>0，因为create输入也会过期。
- Purge产生的生命周期列变化是预期，不纳入“不可变身份”指纹。单独记录purge前后和恢复前后的审计数量，恢复不得新增execution解密访问。

### 财务/预算

金融指纹按稳定顺序与白名单列覆盖目标组织/任务关联的 ledger账户、holds、journals、video_billing_entries、video_quota_reservations、video_quota_buckets及相关API Key用量列；金额均十进制字符串。mutation-only阶段不改上述事实，ledger.CheckDrift=0。

Q1先通过独立预期金额/数量验证GET只结算或释放一次，再冻结指纹；原ACK、消费者重放不得再改变金融/预算事实。mutation unknown不是退款依据。

## 9. 超时、失败与证据输出

所有等待有界。建议 runner 默认：普通命令/屏障60秒、DB due40秒、墙钟lease240秒、单次迁移120秒、单个二进制构建600秒、整轮60分钟。CLI仅允许有限正值，不接受无限等待；最终CI外层应略大于整轮预算。超时保留证据、清理自有资源并非0，不能自动修改时间或跳过场景。

`run.json`：固定C_a/P、runner/harness版本及SHA、两个原archive SHA、overlay前后生产源码清单SHA、Go版本、两测试二进制SHA/build-info、MySQL请求镜像与实际digest/image ID、迁移全清单SHA、展开后的39个场景ID、官方调用0、清理结果。
