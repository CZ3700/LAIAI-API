# Seedance 计费与正文留存核对

## 当前计价行为

管理后台的通用模型目录通过 `relay.ModelPrice` 判断是否定价；火山官方视频网关使用独立的、按组合发布的 `video_pricing_rules`。通用目录显示未定价，不能据此推断视频规则不存在。视频规则必须按供应商范围、公开模型、模式、分辨率、参考视频、服务层级及 Draft 精确命中唯一有效版本。

未配置或未发布有效组合时拒绝受理，不冻结余额、不提交上游；官方参考目录不会自动成为客户售价。继续遵守本轮用户确认：保留现有 USD 售价，新增组合暂不发布。

已配置时，创建前以已核验的画幅、输入/输出时长（或输出帧数）、帧率和最低量计算预留 Token，乘风险系数；客户冻结金额使用当时已发布的 USD 单价和有效倍率。供应商 CNY 预算预留独立计算，不能直接当作 USD 扣客户余额。

成功后按官方返回的 `usage.completion_tokens` 与创建时价格/倍率快照计算应计金额；扣款不超过原冻结额，剩余解冻，超过冻结的差额单独记录由平台吸收。缺失实际用量时进入 `pending_usage`，不以估算值代替。参考视频影响组合价格和预估时长；通用日志输入 Token 为 0 是当前未单独填入输入量的投影，不代表参考视频免费，也不能当作上游每次显式返回了 `prompt_tokens: 0`。

日志详情和体验场的输入量说明已改为“未单列”，删除“0 表示官方不单独计量”的无依据断言；定价页明确参考视频按对应组合计费。通用 Token 统计的历史数字未改写，需以保存的原始上报用量和计费 Token 核对。

核对时本地仅启用 seedance-2.0、seedance-2.5 的 `generate / 480p / input_video=false / default / draft=false` 各一格，风险系数均为 4。该系数用于本地验收的冻结上界，不乘入最终实际用量结算。本次不改变这些单价、版本、倍率或启用状态。

## 最低量创建缺口

核对发现：`QuoteWithMinimumTx` 已按已验证最低量格子产生估价，但 `ReserveTx` 重读普通规则后调用基础 `Quote`，丢失格子最低量，可能使最低量占优的请求估价成功而创建返回 409。该行为是拒绝受理，不是静默低扣或超扣。

修复要求：冻结事务重新解析已验证的最低量来源与完整维度范围，核对来源与金额；不能把调用者传来的最低 Token 当作可信来源。自动时长、adaptive 比例需要完整范围，不能只检查碰巧取得最大值的单格。既有任务的幂等重放继续读取原冻结快照，不按当前价格重新冻结。官方只读目录仍不自动导入最低量规则。

## JSON 留存原因与本地修复

2026-10-18 检查本地组织发现 `capture_history=true`，但 10 月 16 日冒烟初始化把 `retention_days` 设为 1；因此旧正文已过期清理。过期记录的包装密钥已清除，不能把任务结果、请求示例或本地脚本回填为历史实际请求 JSON。

已通过具名管理员接口将该本地组织的历史留存改为 30 天，并验证策略及变更审计落库；同时将本地初始化脚本的留存值改为 30，防止再次初始化时缩回 1 天。该变更适用于后续新请求、新任务；不会延长既有正文或旧任务快照的期限，也不会恢复已清理数据。执行胶囊的独立短期 TTL 保持不变。

JSON 仍使用 Invocation Store 脱敏和信封加密；正常输出/日志不打印秘密。查看正文继续经过组织授权与访问审计。留存期与任务/账务元数据的保存期限不同。

本地验证使用带未知字段的素材组校验请求，在解析阶段返回 422，因此不会创建素材组或调用上游。验证内容：

- 接收 JSON 与响应 JSON 均持久化，并能通过历史正文接口授权回读。
- 两份正文的到期时间均为写入后 30 天。
- 前后任务、素材组和素材操作数量完全一致，无付费生成调用。
- 浏览器在“请求日志 → Seedance 视频 → 全部操作”中能打开该记录，在右侧抽屉显示实际回读 JSON 和到期时间。

该校验请求没有出站调用，因此其“有效出站 JSON”显示未保存是正确行为；它仅验证日志存储与读取，不冒充新的真实视频出片验收。验收证明及截图保存在本地 `.cache/ark-local-smoke/retention-verification.json` 和 `.cache/maas-acceptance/request-json-retained-2026-10-18.png`，不随 PR 上传用户数据库或秘密。

## 最低量修复与验证结果

2026-10-18 已在独立分支 `codex/ark-minimum-hold-consistency` 完成修复。估价保留包内私有、深拷贝的最低量选择范围；冻结事务按该范围重新查询已验证来源和全部适用格子，并校验来源 ID、摘要、最低量和金额。非参考视频路径同时清零历史标量最低量，与估价语义一致；基础 `Quote` 算术接口保持不变。此次未新增迁移、修改售价、导入目录数据或启用新组合。

- 修复前，新增固定维度与自动时长/adaptive 范围两项回归均稳定复现 `video_billing: conflict`；修复后通过，并检查 Ledger、Key、配额和冻结快照。
- 负例覆盖 21 种来源失效、价格或报价篡改；另覆盖自动时长上界不足、adaptive 非最大格缺失、金额不变但最低量证据变化、旧标量非零的纯文生路径。拒绝时无资金、配额或快照残留；旧任务重放不重冻结，实际用量结算仍按原快照扣款并释放余量。
- 总控在独立 MySQL 8.4 测试库执行正式迁移及重放后，实际运行 `TestMySQLRawVideoUsesAggregateUpperBound` 通过；该测试验证同请求 Estimate → Create → Ledger hold → 快照 → 幂等重放，且无上游请求。测试库与本地验收业务库隔离。
- 远端连续运行普通 MySQL 测试和 race 测试时，发现新增服务用例复用了固定请求 ID，撞上前轮保留的全局请求关联主键。已改用现有 `fixture.requestID` 按组织隔离测试请求；保留同一个幂等键及全部资金断言。在不清理旧数据的独立 MySQL 库中先复现第二轮失败，再验证修复后 `-count=2` 连续通过；未放宽生产唯一约束。
- 完整本地门禁通过：`core` / `relay` 的 `go vet ./...`、`go test ./... -count=1`、`go build ./...`，以及迁移 lint。全量 Go 测试不设 MySQL DSN 的部分按既有约定跳过，以上服务级 MySQL 用例已单独实际执行。
- 前端 `npm run build` 及三组回归通过：`test:models` 2 项、`test:playground` 7 项、`test:video-pricing` 6 项。通用目录新增计费范围说明与超管视频定价入口，未改变定价统计或请求 API。

本轮验证零付费调用。CI 结果摘要及前端原始测试输出保存在本地 `.cache/minimum-hold-ci-20261018/`，不随代码上传。
