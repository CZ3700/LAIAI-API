# 取消与删除响应收件箱：A2a 分阶段实施契约

2026-10-26。架构先更新，基线已合入 main `c2cebf6c57adc950ae66dd5de2cfd8ea6cd34c90`（PR #60）。本契约是实施决定，不表示完成验收或启用生产。

## 1. 提交与开关

consumer 独立 PR，固定验收提交 C_a；producer 另 PR。consumer 只有内部登记/Prepare/保存/应用入口，生产 HTTP、后台 claim、配置均不产生新 mutation 登记。测试使用真实生产内部函数造合法登记，不裸插伪 HMAC 或冒充旧新二进制。producer 后续新增严格布尔 LAIAI_VIDEO_MUTATION_RESPONSE_INBOX 默认 false，独立于现有 LAIAI_VIDEO_RESPONSE_INBOX；专池始终配置、消费者始终工作。新格式曾产生后只能回退理解该格式的构建。完整 A2b/A2c 门禁前不启生产。

本批不做 delivery、普通 GET 收件箱替换、DB时间/fence、独立结算调度、涨并发、改价/币种或前端。

## 2. 固定契约与输入

- 新纯函数 ActionContractKey 精确包含 storage_protocol/action/runtime四元组/execution_schema/observation_schema/delivery_schema；固定 ActionDescriptor 有自己的 hash。旧 Descriptor/hash、create input1/observation1继续原 resolver，不变更历史定义。
- 仅支持 inbox-actions-v1 + cancel_task或delete_task + LegacyV1四元组 + 2/1/0。未知组合在claim/发送前拒绝且零HTTP零资金动作；已登记的迟到append只验证归属，不要求当前解释器仍可解释；应用不能解释则blocked，候选在LIMIT前排除，不回退legacy。
- Invocation 新增窄动作 reader：只允许 purpose=execution、direction=effective_request、schema2、worker角色；原 ReadForExecutionSchema/ValidateVideoExecutionSchemaTx/ReadVideoExecutionIdentityTx 对创建的schema1语义保持。元数据身份读取可忽略已过期正文，但不能绕过角色/org/purpose/schema或重新解密过期正文。
- 动作输入属于本次 Operation，PayloadRef 不覆盖 State.EffectivePayloadRef。结构包含schema_version、action、task_id、operation_id、target_upstream_task_id、provider_scope_id、credential_snapshot_id、billing_snapshot_id、upstream_model、固定四元组，以及恢复身份核对必需的非敏感固定事实。凭据、用户提示词和签名URL不进入此结构。
- 使用现有执行输入加密/staging，生命周期为本动作准备时刻起现有24小时执行用途；不以创建历史过期阻止旧任务删除。Prepare在锁外；登记事务锁Task→State→Operation后复核目标/身份，Stage与claim/attempt原子提交。consumer测试显式锁和建立测试claim后调用同一生产登记函数。
- InputIdentityHMAC 用新固定domain，绑定不可变输入元数据、动作/目标、固定账号/凭据/计费快照/基址/模型/四元组。算法domain与key version分开；不修改默认HMAC key版本、不用latest。恢复只读元数据核对，发送前后继producer才读动作明文。

## 3. 数据与原子性

迁移0130已在G1的0129合入main `7688307` 后定号，仅扩展 video_execution_attempts.target_upstream_task_id VARCHAR(128) NULL，沿用旧资源ID排序规则 utf8mb4_bin。不修改0128/历史数据、不引入GORM default、不建提前的交付字段。旧SQL省略列仍为NULL；create-v1必须NULL，新动作必须非空精确目标。新字段为nil时不进入旧create的JSON/HMAC序列，固定golden证明原response-evidence:v1定义不变。

目标以现有Ark受控ID验证为基础，拒绝凭据反射、空白、非法字符/长度。Go逐字节比较；SQL跨旧PAD SPACE列使用可索引等值+OCTET_LENGTH，保证大小写/尾空格变化不会通过。真实MySQL需证明排序规则兼容与查询计划，不以SQLite替代。

独立append只锁不可变登记，不锁Task/Operation、不做账务或可见性动作；inbox+Invocation+application+审计同一专池事务提交。每个Prepared对象只创建一次，对相同证据重试只引用同receipt/HMAC；重复赢家必须验证所有关联。受控历史正文仍仅Invocation保存，留存关闭时仅必要typed事实，不能为了恢复另建明文存储。

应用锁序Task→State→Operation→application；必要素材隐藏/绑定释放走已有领域边界。旧claim可追加不能应用，恢复者只接管同attempt并核对当前权限。任意登记（包括未知协议）阻止legacy重发/应用分流和无证据本地取消释放。未返回响应的已登记动作到期只unknown，不再次DELETE。

该守卫同时覆盖已登记create的明确未发送失败：只有本次生产claim捕获的合法登记可保存typed not_sent后通过create收件箱应用；旧knownUnsent直接入口拒绝任意登记，不可绕过证据退款。取消进入needs_review后换幂等Key仍复用同一未解决操作，不能新建DELETE意图。已知动作格式下到期输入的永久身份错误只隔离本Operation为needs_review并让后续队列继续；不能让一条坏记录反复占据批首、阻断已持久化回执。

## 4. 结果语义

| 结果 | 消费后状态 | 财务与后续调用 |
| --- | --- | --- |
| cancel/delete明确not_sent | 本动作rejected | 不代表原视频未生成，零退款 |
| cancel DELETE 2xx ACK / 404 | 无后续终态证据时保持unknown，原查询可继续 | 不确认cancelled、不按零usage结算，不自动重发DELETE |
| GET已succeeded并结算，再收到cancel ACK | 保持succeeded与原结算 | 零新增资金动作 |
| GET已cancelled且Operation confirmed，再收到ACK | 记录证据消费，保留confirmed | 不重复退款，不用空ReceivedOutcome冒充已消费ACK |
| delete DELETE ACK / 404 | 仅精确target/binding且原任务终态、财务终结时软删 | 不删历史/账务；不重复业务事件 |
| 临时DB/身份依赖无法读 | 保留回执，blocked/backoff | 零资金动作，不扩大HTTP权限 |
| 同attempt矛盾受控证据/目标不符 | 本动作needs_review | 不修改原任务绑定、不套create隔离阻断普通GET |

DELETE accepted 正常可能没有返回 TaskID，登记target提供目标归属，不能套用create缺ID=unknown规则，也不能把登记目标伪造为“上游返回ID”。typed结果transport action必须ActionDelete。重复/冲突检查在terminal幂等短路之前；未确定响应后明确ACK可合法推进证据，矛盾拒绝/接受进入核对。取消成功最终事实只能来自权威GET；mutation reducer不调用ledger。

404只在完整且已由固定适配器分类为accepted/rejected时作为目标缺失确认；截断、非法标识或凭据反射等被降级为unknown的404不得再提升为ACK，更不能据此软删。

保存沿用A1.1单次prepare、脱离caller取消的共享10秒窗口、0/200/800ms三次DB追加，最终失败锁存进程派发暂停；应用失败不触发保存暂停。开关关闭和进程暂停不影响已登记证据恢复。
