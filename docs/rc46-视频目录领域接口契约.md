## 1. 目录宿主与时间/事务责任（主控已冻结）

主控已决定收紧先前草案：对 video 的宿主入口不开放任意 `At` 参数。`ReadCatalogTx` 从 `s.Now` 固定一次 UTC 时间，经 `CatalogObservation.CheckedAt` 共享给同事务通用段；下面各域的 `at` 仅由该值传递，用于有效期判断，绝不接 HTTP 参数或把它当授权版本。

```go
// video/catalog_types.go
type CatalogSubjectRef struct { OrgID, KeyID uint64 }
type CatalogObservation struct {
    CheckedAt time.Time
    Models []CatalogModel       // 仅安全 DTO
    // 内部可附有限别名排除信息；不序列化 cfg/cap 原文。
}

// 普通 /v1/video/models 宿主：拥有共同 1s context、只读 RR 和 Commit。
func (s *Service) Catalog(ctx context.Context, ref CatalogSubjectRef) (CatalogObservation, error)

// /v1/models 宿主：调用者已经建立相同约束的事务；此方法不 Begin。
// 一次读取主体再读配置，时钟由 s.Now 固定；成功结果仍须由宿主在 Commit 后交付。
func (s *Service) ReadCatalogTx(ctx context.Context, tx *gorm.DB, ref CatalogSubjectRef) (CatalogObservation, error)
```

`/v1/models` 在验证 Key 后创建唯一 1s context 与主库只读 RR，先调用 `ReadCatalogTx`，再以它的 `CheckedAt` 和有限别名信息调用仅通用目录的 Tx helper，最后 Commit、检查 parent context，再一次性输出。不得分别创建两个 1s 或两个事务；不得先调用旧 `publicPricing` 再补官方段。业务查询最多 18 SELECT，不含原 VerifyKey/审计。

`CatalogModel` 保留原诊断字段及新增 publication/actions；版本未解析用 nil，正常无需最低规则用指向空字符串。所有数组初始化为空数组，纯 DTO 不包含 cfg/rule/scope/credential 指针。`CatalogObservation` 不实现缓存，也不返回可复用的发送许可。

`CatalogModel.Provider string` 仅保留已验证固定渠道的两种安全 provider 值并标记 `json:"-"`，宿主用于 `/v1/models.owned_by`；不返回渠道 ID 或其他内部身份。

不再保留 `CatalogRequest{Subject, At}` 宿主签名或历史时间 HTTP 选项。`Catalog` 不提前另取第二个时间；它只建立事务并委托 `ReadCatalogTx`。

## 2. video 所属的纯能力/组合规则

```go
type PublicationCell struct {
    Mode, Resolution, ServiceTier string
    InputVideo, Draft bool
}
type PublicationCapability struct { // 字段私有，只有构造器可产生有效对象
    // 原 cap、已校验 bounds 和组合能力；不带 DB 句柄。
}
func ParsePublicationCapability(cfg ModelConfig) (PublicationCapability, error)
func (p PublicationCapability) Cells() []PublicationCell
func (p PublicationCapability) Supports(cell PublicationCell) bool
func (p PublicationCapability) BillingContext(scope ProviderScope) (videobilling.PublicationContext, error)
```

提取自 `server.validateVideoCapability`、`priceMatrix`、`priceCellSupported`，管理端保留薄包装而不保留第二套规则。构造器是纯函数：配置合法性错误可形成 `capability_invalid`，不访问 DB、网络或凭据。固定 variant profile、bounds、24 fps、上游名等继续由现已核验数据约束。

`Cells` 必须只按 capability 的有限域枚举，不从无效历史价格反向扩能力；cap 中的字符串/数组先受上界校验。内部模型字段可用于既有营销/管理映射，但普通 DTO 只输出 contract 允许内容。

渠道身份纯校验由 video 拥有：输入仅是 relay 安全 facts，规则固定平台所有权、启用、两种既有 provider、官方 endpoint。Create 在现 Channel UPDATE 锁读后转换相同 facts 再判定；不能把目录 facts 当凭据选择结果。

## 3. identity 与 relay 窄 reader

复用 A1 真实主体 reader，不调用 grouped CandidateResolver 后吞 legacy 错误。必要 adapter 只复制明确字段，不凭空制造 legacy APIKey。

```go
// identity 已有，3 SELECT：key、Org/member、entitlement。
func ReadRoutingCandidateSubjectTx(ctx context.Context, tx *gorm.DB,
    orgID, keyID uint64, at time.Time) (RoutingCandidateSubject, error)

// identity 新增，1 PK SELECT；不把 group_name 与 routing_group_id 混同。
func ReadVideoBillingGroupTx(ctx context.Context, tx *gorm.DB, orgID uint64) (string, error)

// identity 所属共享纯语义；原 AllowsModel 与目录都委托同实现。
func LegacyModelAllowed(modelLimits, model string) bool

// relay 新增，1 SELECT + 有界 EXISTS，只读摘要不读密文。
type VideoCatalogChannel struct {
    ID uint64
    PlatformOwned, Enabled, OfficialArkEndpoint, HasUsableCredential bool
    Provider string
}
func ReadVideoCatalogChannelsTx(ctx context.Context, tx *gorm.DB,
    ids []uint64) ([]VideoCatalogChannel, error)

type VideoCatalogRatio struct { Model string; Ratio decimal.Decimal }
func ReadVideoCatalogRatiosTx(ctx context.Context, tx *gorm.DB,
    groupName string, models []string) ([]VideoCatalogRatio, error)
```

IDs 正数、严格升序、去重、最多 4；模型只允许可信 canonical 4 项，缺渠道行省略（video 形成 binding blocked），不能把 SQL 错误当缺行。倍率 reader 用一条至多 4 行的派生表 LEFT JOIN；无配置/非正值保留原 EffectiveRatio 的回退语义，SQL 错误不能回退 1。输出每个请求模型恰一项，Go 检查原始身份精确相等，防 PAD SPACE/case collation 扩大命中。

凭据摘要使用固定 SQL CASE：有任何 credential 子行时只检查 active+非空子行；全部禁用不得靠 legacy 密文复活。无子行才检查 channels legacy 非空。只查非空事实不扫描/反序列化密文；该布尔只影响 create 动作资格，不承诺能解密或官方会接受。

主控已决定：video 直接调用 identity/relay/videobilling 所属窄 reader（现 Service 已依赖这些域），不为单一宿主额外造三套接口注入。video/server 不得裸查 identity/relay 私表，也不为此次四模型组合增加与 routinggroup 的循环依赖。固定官方渠道的 legacy 路径不新增 `Models` CSV 限制；固定 `cfg.ChannelID` 仍是官方绑定来源。

## 4. videobilling 所属价格快照与纯资格

本域不能 import video/server。其 publication context 只包含计量校验需要的数字与事实，不能接 `ModelConfig` 或任意闭包。

```go
type CatalogTariffRef struct { ProviderScopeID uint64; Model, PricingVersion string }
type PublicationBound struct { Resolution, Ratio string; Width, Height int64 }
type PublicationContext struct {
    CapabilityVersion string
    Ratios []string
    MinDuration, MaxDuration int
    FPS int64
    Frames bool
    MinFrames, MaxFrames, FrameStep int64
    Bounds []PublicationBound
    MaxInputVideoDurationMS int64
    FXUSDPerCNY decimal.Decimal
    FXVersion string
    FXObservedAt time.Time
}
type CatalogTariffSnapshot struct { /* 私有 rules/sets/cells/at/refs */ }
func ReadCatalogTariffsTx(ctx context.Context, tx *gorm.DB,
    refs []CatalogTariffRef, at time.Time) (CatalogTariffSnapshot, error)

type CatalogPublishedPrice struct {
    RuleID string // 既有公开 price_rule_id；不暴露内部规则对象
    RetailUSDPer1M decimal.Decimal // 基础价，客户倍率由 video 另乘
    PricingVersion, FormulaVersion, MinimumRuleVersion string
}
type CatalogCellResult struct {
    Price *CatalogPublishedPrice  // blocked 必须 nil
    Reasons []CatalogTariffReason // 本域枚举，由 video 映射稳定客户码
}
func (s CatalogTariffSnapshot) Evaluate(key PricingKey,
    p PublicationContext) (CatalogCellResult, error)

// 真正 plan 的已选规则复核；最多再读 set/cells 两条。
// 与 Evaluate 共用本域纯验证，不重选价格或发起 Reserve。
func ValidatePublishedRuleTx(ctx context.Context, tx *gorm.DB,
    rule PricingRule, expectedKey PricingKey, expectedVersion string,
    p PublicationContext) error
```

`refs` 成对排序去重、最多 4；有效 rules 不提前按 version 过滤（否则漏跨版本 overlap）；三查询上界规则 257、sets 17、cells 32001，多一条立即整体错误，不截断。读取到 snapshot 后不提供 Rules()/JSON marshal/原始 source 字段 getter；安全输出只有基础客户价和已有版本信息。supplier/source/FX 内部用于验证，不能进入目录 HTTP。

`Evaluate` 没有 DB、解密、HTTP；校验唯一规则、version、validRule、全 ratio 最低覆盖与可计量边界。`CatalogMinimumTokens` 保持唯一最低覆盖算法，允许其内部拆固定 missing/invalid 分类，不能在 video 再实现。实际 QuoteWithMinimumTx 的请求用量与 ReserveTx 锁内重算保持不变；最大用量 probe 只用于规则有效性，不是报价。

主控已采纳 billing 精确补充：`ValidatePublishedRuleTx` 必须精确比较 `rule.PricingKey` 与 `expectedKey` 的全部字段（scope/model/mode/resolution/input_video/service_tier/draft），不能仅比 version 或依赖旧 SQL collation 的匹配结果。

非参考视频分支先清除旧 `MinimumTokens`，与既有 `QuoteWithMinimumTx` 语义一致；每个合法 ratio 分别构造 duration 和合法 frames 两个互斥 `MeteringInput` 调用 Quote，不能同时填 OutputDurationMS 与 OutputFrames。仅 `Frames=true` 时做帧数探针；范围须 MinFrames>0、MaxFrames>=MinFrames、FrameStep>0。探针采用 `MinFrames + ((MaxFrames-MinFrames)/FrameStep)*FrameStep`，即 MaxFrames 内实际可达的最大步进值；先证明非负差值及乘加不溢出，再计算，不直接假设 MaxFrames 可达。

参考视频保持现有明确限制：`QuoteWithMinimumTx` 对 input_video=true 拒绝 frames。本批只校验 duration 的完整 minimum 覆盖，不因 capability.Frames=true 把合法 duration 组合整组 blocked，也不启用 reference frames。目录模型级 `frames` 能力不构成所有输入组合都可使用帧数的许可，验收与文档不能作该承诺。

营销用同一纯 capability/cell/最低覆盖验证，以基础价倍率 1 输出；无 Key/Org/Feature/Policy 依赖。营销是否采用新批量 reader 可以独立落地，但不能把现有查询数说成官方目录的 15 条。

## 5. 错误映射和 fail-closed

| 原因 | 领域处理 | 目录/宿主处理 |
| --- | --- | --- |
| 缺主体、Org/member失效、Key停用/到期、非合法legacy | identity facts/固定拒绝 | 整请求拒绝，不能返回营销fallback |
| 缺 entitlement | 使用既有 DefaultEntitlements | 与真实 SQL 错误区分 |
| 缺 Policy/关闭 | video 合法缺配置事实 | 仅 create execution_disabled；read/estimate保留 |
| capability、binding、规则、覆盖事实不可发布 | 纯规则稳定原因 | 保留诊断行/blocked组合，不暴露原文 |
| invalid reader参数、裸DB、DryRun、丢依赖 | fixed invalid sentinel | 整请求失败，不能变零行 |
| 超行数/字节边界 | fixed limit sentinel | 整请求503，不能截断发布 |
| SQL/连接/Commit失败 | 安全 unavailable sentinel | video envelope503；发现接口固定 `model catalog unavailable` |
| parent取消/期限 | 保留 errors.Is(ctx错误) | 零值结果、不发半页 |

identity/relay自有错误映射到 video 的 `ErrCatalogInvalid/Denied/Limit/Unavailable`；不要用 err.Error() 包 SQL。普通用户 reason codes 只有正式实施契约枚举。所有新查询 session logger.Discard；不是全局修改日志。

读取后须精确校验请求身份。旧 MySQL collation 的大小写或 PAD SPACE 相似命中，若规则、minimum set、组名或模型与请求不完全相同，属于 reader 完整性失败，整体返回固定 unavailable；不能丢弃后当作无配置或倍率 1。`minimum_rule_invalid` 只用于身份已精确对应、但证据或规则内容失效的组合。保留有索引的等值谓词，再由领域代码完成精确校验。

## 6. SELECT 预算与实际接点

| 官方业务读 | 最大 SELECT | 归属 |
| --- | ---: | --- |
| 当前 subject / principal / entitlement | 3 | identity |
| config LIMIT65 / fixed scopes≤4 / Policy单Org | 3 | video |
| fixed channel与凭据EXISTS | 1 | relay |
| rules LIMIT257 / sets LIMIT17 / cells LIMIT32001 | 3 | videobilling |
| group_name / 最多4个倍率 | 2 | identity + relay |
| portrait路由/shared/default/安全管理摘要 | 3 | video，仅本域表；复用scope/Policy |
| **官方段** | **15** | 无模型 N+1 |
| 发现接口旧通用 prices/channels/meta | **+3** | server 原算法拆 Tx helper |

同一主库只读 RR，总 parent 1s；每 SQL ≤200ms（包含连接/执行/Scan，执行后检查并取消），CPU解析仍受 parent。新DBchain一次 Session(NewDB,Context,Discard)，保留同ConnPool。无 TTL、UPDATE锁或外部请求。总1s不因存在15条SQL延长到3s，超时就安全整体失败。

`plan` 的 caller context/事务不改为目录1s/只读RR。插入点仍是非幂等重放分支内的原config/scope/normalized tuple/ResolvePricingTx之后；新纯校验+两个有限minimum读取，不增加Org/组 UPDATE锁。Create锁Channel之后复用身份纯检查；Estimate只观察固定channel摘要。幂等成功路径继续先返回旧回执，价格下线不能多冻结/丢原回执。

## 7. 最小分工与验收对齐

1. video线：纯capability/cells、目录组合器、HandleModels和plan接点，独占service/reads旧文件；不碰worker/inbox。
2. reader线：identity/relay新文件及原AllowsModel薄委托，真实Tx/字节/期限/字段白名单测试；不碰签发认证开关。
3. billing线：opaque快照、publication context、共同纯校验、minimum分类与边界测试；不改金额算法。
4. 主控宿主线：通用Tx拆分、营销薄包装、两个入口和独立MySQL；实际RR1792、第二连接变更同快照、15/18 SQL、真实EXPLAIN、无上游/Reserve/KeyUsage变更；不以两个错误实现互相对比作oracle。

首批需要一起合入真实目录、plan及营销共享纯规则；不能只交付无人调用reader。固定四模型字段/组合/Decimal期望由独立fixture声明；部分published、无价、跨版本重叠、reference最低覆盖缺口、scope/Feature/Policy不同动作资格，以及关闭后同body幂等均是验收必需项。

## 8. 管理端纯函数兼容约定

`video.ValidatePublicationCapability(cfg ModelConfig, cap ark.Capability, bounds map[string]Dimensions) error`承接现管理端纯能力校验；`video.PublicationCellSupported(cell PublicationCell, cap ark.Capability) bool`承接现priceCellSupported。目录只发布受支持的有限组合；管理端原完整网格与历史价目的展示保留，不能因提取纯函数丢失禁用格或历史维度，也不能反向扩大目录能力。`ParsePublicationCapability`须委托同一校验，不形成第二套有效性规则。
