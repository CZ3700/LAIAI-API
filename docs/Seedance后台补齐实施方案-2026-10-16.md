# Seedance 后台补齐实施方案

评审稿，2026-10-16。本轮交付方案，不表示功能已经实施、正式价格已经发布或新能力已经验收。范围包括此前发现的定价与日志缺口，以及私域素材库、真人认证、官方同步、动账流水和测试页。支持 Seedance 2.0、2.5，保留现有通用模型功能。

实施前以已验收的 Ark 集成代码和冒烟修复 PR 的确定提交为共同基线；不在本地存在其他修改的主工作区直接并行开发。当前原型参考用户提供的九张截图及参考站请求日志页面。参考站用于交互参考，火山接口语义以官方文档为准；参考站访问令牌不得进入代码、文档、测试 fixture 或日志，也不作为火山凭证。

## 1 交付范围和完成标准

| 模块 | 本轮需补齐 | 完成标准 |
|---|---|---|
| 视频定价 | 分辨率、有无参考视频、模式、服务档位、Draft、最低用量版本、售价与成本 | 后台发布后新任务报价生效；旧任务价格不变；缺价或缺计量规则不可启用 |
| 私域素材库 | 真人与虚拟两类组、名称描述、上传、官方同步、搜索筛选、预览、更新删除 | 从后台可完成组与素材生命周期，平台 ID 可用于实际视频请求，所有权不串租户 |
| 真人认证 | 三步向导、官方 H5、查询结果、同步生成组、使用许可 | 真人本人认证；后端查证成功后绑定官方组；未获有效使用许可不放行引用 |
| 请求日志 | 通用模型与 Seedance 视频两个 tab、请求详情、JSON、任务与账单关联 | 成功、失败、重放、查询、取消删除均可查；创建响应不被轮询覆盖 |
| 动账流水 | 类型、四个方向、四类状态、查询汇总、关联详情 | 冻结、扣费、解冻可对照；失败操作不虚增消费；冲正可追溯；资金不重复统计 |
| 测试页 | 新 Ark 契约、报价确认、幂等键、完整任务状态、产物预览 | 用户直接从页面完成创建、查询、查看产物与账单，无需脚本补步骤 |

沿用原 PDF 第六条方式 D：下游使用平台域名和平台 Key；官方凭证只在服务端；请求前原子校验并冻结额度；根据真实官方 usage 结算，再核对供应商账单。依照现有架构，客户账本仍为 USD，供应商成本为 CNY；不新增另一套客户余额。

## 2 已核对现状和需要更正的口径

1. 后端 `video_pricing_rules` 已有场景维度，现有定价 UI 却仍操作旧 `model_prices`。当前真实冒烟只发布了两模型的 480p、无参考视频规则，不能视为完整价格矩阵已上线。
2. Ark 已将请求和响应正文放入加密 Invocation Store，但后台没有通用正文读取接口。出站 JSON 当前只保存执行用途副本；历史查看不能借用 worker 权限。
3. 视频兼容 `invocations` 行主要在成功结算后写入，不能作为完整请求日志来源。测试页会在成功轮询时覆盖创建 JSON。
4. 素材域已有虚拟组、URL 导入、Get 轮询、真人 H5、使用许可和引用锁基础；缺少官方 List 同步、Update、完整 DeleteAsset、用户上传流水线及后台页面。
5. 当前 ledger 的冻结、释放及零额结算并非全部产生 journal；旧流水 API 只查 journal，因此不能完整呈现冻结过程。历史 `balance_after` 还可能是分片快照，不能直接声称是每笔之后的准确组织总余额。
6. 官方明确视频模型不单独统计输入 Token，`total_tokens = completion_tokens`。兼容 `prompt_tokens=0` 可以保留，但页面必须说明其含义；不生成虚假的参考视频输入 Token。[官方查询接口](https://docs.volcengine.com/docs/ark/get-video-generation-task-api?lang=zh)

本方案涉及的架构调整在实施阶段先更新 `docs/整体架构设计.md`，再落业务代码、OpenAPI 和 SQL。本文是评审提案，不替代当前架构事实源。

## 3 页面与操作设计

### 3.1 私域素材库

新增独立页面，入口放在模型管理区域。顶部为“真人素材 / 虚拟素材”两个 tab；项目选择器显示用户已授权的项目别名，内部绑定固定供应商作用域。超管额外可见账号别名，避免多个账户的 default 项目混淆。

左侧显示素材组：名称搜索、状态、创建、同步、名称、描述、素材数量和最近同步时间。右侧显示选中组：名称搜索、图片/视频/音频筛选、状态筛选、上传入口和分页列表。统计数字以相同筛选条件下的全量记录为准，不能将当前页数量冒充全库数量。

素材行显示缩略图、名称、平台素材 ID、媒体类型、大小/时长、可用性、失败原因、上传时间、更新时间及操作。展开可看来源、校验结果、同步时间、引用情况；来源链接经过权限校验并脱敏。上游 ID 仅在内部运维视图显示。图片可缩放；视频和音频支持播放与 Range，使用受控预览接口，不把官方临时签名 URL 当永久链接。

上传支持本地文件和 HTTPS URL。流程是私有暂存、格式/大小/安全校验、媒体探测、生成不可变媒体引用，再调用火山 CreateAsset。上传成功不等于官方注册成功。已有可信登记接口继续用于受信任的内部工作流，不能把它当成已实现安全扫描。

私有对象供官方导入时使用时效受控的 HTTPS 下载地址，期限覆盖该次注册窗口；签名地址只存加密执行证据，绝不跟随上游 Authorization 头。上传完成回执必须由服务端核对对象大小、哈希和校验状态，不能信任浏览器自报成功。过期暂存对象按独立生命周期清理，不误删仍被任务引用的媒体。

弹框宽度约 680–800px，最大高度不超过视口减 48px；内容区滚动，标题和底部按钮固定。移动端使用全宽布局，底部确认按钮始终可达。

### 3.2 虚拟素材组

填写名称与描述后直接创建。新名称与官方同步，按官方限制校验：名称最多 64 字、描述最多 300 字，不静默截断。后端使用 `CreateAssetGroup(GroupType=AIGC)`；只有官方确认和本地关联完成后显示创建成功。超时可能已受理时进入待确认，不自动再建一组。

官方首次开通需要其要求的授权函和权益；页面通过能力接口显示是否已就绪，不能由前端“同意”复选框伪造官方开通。[创建素材组](https://docs.volcengine.com/docs/ark/create-asset-group-api?lang=zh)

### 3.3 真人素材组

采用截图中的三步向导：

1. **创建认证任务**：填写名称、描述，暂存到平台认证会话；调用官方 CreateVisualValidateSession。
2. **完成真人认证**：显示官方 H5 二维码、打开入口、有效期和状态。由真人本人完成；浏览器回跳只触发后端核验，不作为认证成功证据。
3. **生成素材组**：后端调用 GetVisualValidateResult，取得并绑定官方 GroupId；再调用 UpdateAssetGroup 同步之前填写的名称、描述。名称同步失败保留同一个组并重试可幂等的更新，不重新认证或创建重复组。

界面分别显示“认证状态”和“使用授权状态”。身份认证成功不替代用途、期限、撤销及复核有效期等使用许可。仅在认证、许可和媒体校验均满足条件后允许引用。认证会话的临时链接只向有权操作的人按需返回，使用 no-store，不放入普通请求日志。

当前官方真人指南包含图片、视频、音频；页面选项以当前账户权益与目标模型能力为准，不硬编码“真人仅图片”。[真人素材指南](https://docs.volcengine.com/docs/ark/guide-preview?lang=zh)、[H5 创建接口](https://docs.volcengine.com/docs/ark/h5-create-visual-validate-session-api?lang=zh)、[更新素材组](https://docs.volcengine.com/docs/ark/update-asset-group-api?lang=zh)

### 3.4 素材状态

保留现有 API `status` 的兼容含义，新增本地处理阶段及上游原始状态，供页面展示。

| 页面状态 | 必须有的事实依据 |
|---|---|
| 上传中 | 本地上传或受控远程导入未完成 |
| 核验中 | 本地安全检测、媒体探测或真人认证正在核验 |
| 注册中 | 已提交官方注册，或官方返回 Processing |
| 可用 | 官方 Active、可信媒体证据完整、所需使用许可有效 |
| 失败 | 明确的上传/校验失败或官方 Failed；展示安全原因和可执行操作 |

另有“待确认、删除中、已删除、授权过期”等辅助状态，防止将网络超时硬塞成失败或将授权失效继续标为可用。官方本身只有 Active/Processing/Failed 等已核实素材状态，本地阶段不是伪造的官方审核进度。[素材列表](https://docs.volcengine.com/docs/ark/list-assets-api?lang=zh)

## 4 火山同步与归属规则

素材管理使用独立 AK/SK 签名；推理 API Key 不能替代。后端使用固定域名、服务、区域和 Action 白名单，客户不能指定任意 Action、项目或上游地址。[鉴权文档](https://docs.volcengine.com/docs/ark/base-url-and-authentication?lang=en)

“直接同步”定义为：平台创建、修改和删除通过官方 API 执行；平台按账号/区域/项目拉取官方组与素材状态，落本地租户索引供查询。它不表示把整个官方账号资源默认开放给所有下游。

- 已有平台映射的官方资源自动更新到原属 Org。
- 超管可启动账号项目范围的发现任务；未映射组进入“待归属资源”，由超管明确分配 Org 并留审计依据。
- 租户“同步”只刷新其已归属资源。若明确配置为单租户独占项目，可使用经过审计的项目归属规则；默认采用组级归属。
- 不按组名称、发起同步的人或当前登录组织猜归属。任何 scope/资源 ID/游标都不能绕过仓储层 Org 约束。
- 官方资源状态为上游事实源；Org、许可、可信媒体和客户 ID 是本平台事实源。平台正在执行 rename/delete 时，不让旧分页数据覆盖新意图。

官方已存在的真人组导入后，可能没有平台 H5 会话。需增加 `authorization_origin=platform_h5|imported_verified`，由受信任的官方/内部核验记录绑定该真人组的有效许可、来源、期限和复核时间。Org 分配本身不授予使用权；不能伪造一条 H5 成功会话来绕过现有检查。导入组也必须通过当前许可和媒体校验才能展示为可用。

同步使用 ListAssetGroups/ListAssets 的 `MaxResults + NextToken`，固定项目、筛选和排序，记录断点；不与页码参数混用。按账号集中限流，作业带租约和 fence；相同 scope 的并发同步合并或排队。页面只显示作业进度，不因每次刷新页面触发全量扫描。[素材组列表](https://docs.volcengine.com/docs/ark/list-asset-groups-api?lang=zh)

单次分页未出现的资源只标记待复核，不能立即删除。需要单独查询确认；周期全量校准补足排序变化和分页非快照的一致性缺口。接口超时、权限变化、循环游标、部分页失败均保留断点和安全错误，不能把部分结果标成完整同步。

从官方导入的素材先完成归属与元数据校验；官方临时 URL 和列表字段不证明视频真实时长、文件不变或授权有效。建立可信媒体证据后才允许进入任务计价和引用。

删除使用本地删除意图和引用屏障：检查在途依赖、标记 deleting、写 operation 同事务完成；上游 HTTP 在事务外。结果未知时保持屏障。删除确认后留 tombstone，保留旧任务、日志和财务引用。默认禁止非空组删除；显式级联需展示影响范围并确认，服务端重新检查，官方真人组删除限制照常执行。[删除素材](https://ark.volcengine.com/region:cn-beijing/docs/delete-asset-api)、[删除组](https://docs.volcengine.com/docs/ark/delete-asset-group-api?lang=zh)

“空组”不能只查本地索引：必须先完成官方逐页复核，发现变化或不确定即拒绝。官方 DeleteAssetGroup 会级联且没有跨系统原子的“仅当为空”条件；存在官方控制台等外部写入者时，不开放自动空组删除。此时删除必须走明确的整组删除流程，展示官方最新清单并告知级联范围；确认后再次复核，有差异须重新确认，不能宣称消除了上游检查与删除之间的竞态。无法证明整组归属当前租户时拒绝级联。

## 5 请求日志与 JSON 详情

统一“请求日志”入口，保留“通用模型”，新增“Seedance 视频”tab，覆盖 2.0、2.5；模型筛选再区分具体版本。

Seedance 列表以**每次 HTTP 请求**为单位，来源 `api_request_logs`。默认展示创建请求，可筛选全部操作、查询、取消、删除、素材操作等；任务汇总可另提供视图，不混淆“一次请求”和“一个异步任务”。幂等重放仍有独立请求记录，并指向同一个任务，不能生成第二笔消费。

筛选项：请求 ID、任务 ID、平台 Key ID、模型、操作、HTTP 状态、任务状态、账务状态、时间范围。列显示请求 ID、任务 ID、Key 名称/脱敏标识、模型、请求结果、任务状态、产物状态、任务关联结算金额和时间。跨多条请求重复出现的任务金额仅作关联展示，不按日志行相加。日志页不将“本期查询到的历史任务金额”称作本期消费；期间消费跳转流水并按真实资金影响时间统计，详情附 as_of。

内部 worker 轮询列为任务执行尝试，不伪装成客户 HTTP 请求。任务软删除后日志与账务关系仍可读，不能直接复用隐藏 tombstone 的任务 GET；产物入口停止开放。未确认结算金额用 null，只有确认免费才显示 0.00000000；净扣款由结算及追加调整生成，不使用旧 Invocation 摘要代替。

点击请求 ID 打开详情抽屉，固定摘要区展示 Org（超管）、操作者、Key ID、模型、请求时间、耗时、HTTP 状态、任务状态、价格版本和冻结/实扣/释放。三个 tab：

| tab | 内容 |
|---|---|
| 请求接收 | 当次客户提交的规范化且脱敏 JSON；允许的安全请求头；请求 ID；幂等重放标识。授权用户可展开实际出站 JSON及每次上游尝试，保留时间和来源 |
| 任务结果 | 当前任务状态、完整时间线、产物有效性、视频计费 Token、计价维度、价格快照、账务明细和最后观测时间；明确这是当前结果 |
| 接口响应 | 当次 HTTP 的状态和实际平台响应 JSON，创建时的 202 永不被后续查询覆盖；上游响应按尝试独立查看，内部字段按角色白名单处理 |

JSON 支持格式化、折叠、搜索、复制和受控下载。新请求在鉴权与大小检查后、业务结构体解码前采集合法收到的 JSON，再脱敏保存，避免结构体重序列化丢失字段。参数、能力或额度拒绝也记录可合法留存的业务正文；未认证、超限和不可解析正文只记录安全元数据及未采集原因。返回的是已脱敏 JSON，不宣称逐字节保存原始 HTTP。旧 typed request 重序列化记录标记为 legacy_canonical_json。

普通用户看平台字段；不能透过上游响应正文泄露官方资源 ID、账号、签名 URL 或凭证。客户 JSON 可由本组织有日志权限的成员读取；有效出站及原始上游证据仅限实名超管。请求头采用白名单，Authorization、Cookie 永不保存，幂等键只展示是否存在及不可逆关联标识。

正文通过专门按需读取接口调用 `ReadForHistory`，每次解密前后写访问审计，与总体 audit_events 关联访问 ID；审计失败不返回明文，响应 `Cache-Control: private, no-store`。元数据接口不夹带正文，查看元数据不额外解密。会话和 Org 权限服务端解析，不信任请求体中的 actor/org；公共平台 API Key 不获得后台跨租户或内部原文权限。前端正文仅存当前内存，关闭抽屉、切换组织或退出后清空，不进入 localStorage、埋点、前端异常上报。

正文 section 固定为 client_request/client_response/effective_request/upstream_response，用途固定为历史查看。后端校验 Org → request → task → attempt → payload 的完整关联；不能接受任意 payload_id 或对象路径，也不能因某个 payload 的 request_id 等于 worker attempt ID 就错误归属。幂等重放自身收到的正文与首次创建正文分别标识，不能静默互换。

未来创建请求在 history 留存开启时，为有效出站 JSON 同时保存 history 副本和执行副本，各自用途、期限独立。旧任务没有历史副本就显示“未保存”，已清理的显示“已过期”，禁留存显示“未开启留存”，访问不足显示“无权限”；不能用当前配置重新拼一份冒充当时出站 JSON，也不能越权读取 execution。

## 6 视频定价和用量展示

新增“Ark 视频定价”页，完整规则键为：供应商作用域、模型版本、任务模式、输出分辨率、有无参考视频、服务档位和 Draft。按已核验能力展开组合；480p/720p 分别显示，即使单价相同。2.0 基础分辨率与视频输入组合共 8 格，2.5 共 6 格；高级模式另行展开并验证，不默认开放。

每行显示启用状态、供应商 CNY 成本、客户 USD 售价、版本/生效时间、最低用量规则、公式版本和覆盖情况。组织倍率与 FX 分列。旧模型定价页明确标注官方 Ark 使用此处规则，避免修改旧表后误以为已生效。

后台提供“编辑草稿 → 校验组合和预览报价 → 发布新版本 → 查看历史”。售价默认空，不将冒烟的零加价汇率折算价当商业默认。改价复用供应商作用域，不重置共享预算；并发发布用 expected_config_version 拦截旧表单覆盖。每个已启用组合必须恰好匹配一条价格，缺失、重叠或缺少可信计量规则均不能发布。

最低 Token 不能用一个固定常数覆盖所有参考视频情况。新增版本化最低量规则集，覆盖模型、分辨率、比例、输出时长及必要帧率维度；记录官方来源、取得时间、核验人、精度和覆盖区间。只有官方可证实的精确单元或公式才允许计算，不自行插值或从四舍五入的价格例子反算。[官方计费规则](https://docs.volcengine.com/docs/ark/model-pricing?lang=zh)

```text
基础估算 = ceil((可信输入视频时长 + 输出视频时长) × 输出宽 × 输出高 × FPS / 1024)
准入预留量 = ceil(max(基础估算, 已核验最低用量) × 风险倍率)
客户理论费用 = 官方 completion_tokens × 创建时 USD 售价 / 1,000,000 × 创建时倍率
客户实扣 = min(客户理论费用, 客户授权冻结额)
平台承担差额 = 客户理论费用 - 客户实扣
供应商估算成本 = 官方 completion_tokens × 创建时 CNY 成本价 / 1,000,000
```

风险倍率和最低量仅用于预估预留，不再叠加到官方实际 usage 上；缺 usage 保持待补量，不能按零值或估算实扣。客户实扣仍不超过授权冻结，差额承担和供应商实际账单在内部财务视图体现。客户最终售价不因晚到的供应商折扣或汇率变动重算。

duration=-1、ratio=adaptive 等请求必须解析可信的适用条件，或对完整、已核验的可能输出覆盖域计算保守最大值。缺少任何可能落入的规则域则拒绝准入，不假设最低量对时长或分辨率必然单调，不自行插值。

日志主指标改为“视频计费 Token”。兼容输入 Token 显示“0（官方不单列）”；另显示参考视频数量、总时长及其来源、输出分辨率/尺寸/FPS/时长、命中价格档位和估算/实际的区别。不得把参考视频估算量伪装成官方单独输入量。

本次已找到官方链接的最低量表与计算器，但全量表跳转登录，具体数值尚未取得。参考视频的开发和模拟测试可继续；正式启用需先取得可复核的官方规则数据并完成覆盖验证。

## 7 动账流水

保留 USD 账本为唯一资金事实源。页面可选择 CNY 折算展示，但明确标为折算并附 FX 版本；不能把 USD 数字换上 CNY 标签。供应商 CNY 成本、资源包抵扣和客户 USD 收费分开。

筛选包括关键词、业务类型、方向、状态、原因、安全错误码、关联对象类型与 ID、时间范围。四方向：入账、冻结、扣费、解冻。四主状态：成功、失败、冲正、处理中，详情同时保留原始操作状态、部分冲正金额和待核对原因。

业务类型覆盖现有真实来源：充值、赠送、人工授信/扣减、调用预冻结、调用扣费、差额解冻、确认免费后的全额解冻、退款、借项/贷项调整、冲正。仅为实际已接入的业务产生记录；内部账户分片调拨不混入客户充值/消费合计。

列表显示时间、类型、方向、请求金额、实际影响金额、币种、状态、原因、说明、关联请求/任务/订单和详情。详情串起同一笔冻结、扣费、解冻和调整。顶部单独显示当前账面余额、冻结金额、可用余额，以及筛选区间的入账、扣费、退款、净变动；冻结流量另外列示。

提供按筛选条件导出 CSV 的异步作业，固定导出时点和币种口径，记录操作者与范围；下载鉴权并设置有效期。导出只包含有权查看的财务元数据，处理表格公式注入，不混入请求正文、密钥或供应商内部成本。

| 动作 | 账面余额变化 | 冻结额变化 | 可用额变化 |
|---|---:|---:|---:|
| 入账 A | +A | 0 | +A |
| 冻结 H | 0 | +H | -H |
| 从冻结扣费 C | -C | -C | 0 |
| 释放剩余额 R | 0 | -R | +R |
| 直接扣费 A | -A | 0 | -A |
| 退款/贷项 A | +A | 0 | +A |

例如冻结 2 USD、实扣 0.7 USD，展示冻结 2、扣费 0.7、解冻 1.3；消费合计为 0.7。扣费与释放是同一原子结算的展示分量，不假定数据库存在两个可见中间余额。

冻结操作成功不表示视频成功；视频失败但退款/解冻成功，流水应显示解冻成功。失败或处理中来自真实操作记录，不能从成功 journal 推造。提交结果未知保持待核对，不能先判失败再重扣。冲正通过新的反向分录关联原记录，原 journal 永不覆盖；统计保留原金额与反向金额，不同时排除原支出又计退款。

旧分片余额不能当组织逐笔余额。新记录若要展示“变动后组织余额”，必须由统一组织资金序列/一致性边界下的快照证明；否则显示物理账户范围与可信度，或留空。当前组织总余额独立查询，不通过页面累计历史行猜测。

## 8 接口契约草案

后台浏览器统一使用登录会话入口 `/api/video/...`，服务端解析 Org 和用户；与 `/v1/video/...` 平台 Key 入口复用同一应用服务，禁止绕过权限直接写表，也不在浏览器生成临时平台 Key 自调用。超管跨组织入口使用 `/api/admin/video/...`，明确选定并审计目标 Org。金额一律十进制字符串，时间统一 RFC3339 UTC、界面本地化。

素材控制面引入受信任 CallerContext，区分 session_user 与 api_key，保存真实创建者和所属 Org。现有 CreatedByKeyID/KeyID>0 校验需调整为主体校验；会话操作不能填假 Key ID。旧数据保留 api_key 创建者。H5 敏感入口默认仅原创建者读取，同组织的明确管理角色代查需理由和审计；普通成员身份不自动获得二维码。

所有资金入口覆盖充值、普通调用、Ark 和已有调账。Ark 供应商账单更正继续使用既有双人复核；通用管理员 add/subtract/override 当前是单操作者入口，本轮如接入只统一资金影响记录与既有权限，不谎称它已有双人复核，也不新增直接 UPDATE 余额的入口。将通用调账升级双人复核属于另行明确范围。

历史回填仅从可信 journal、hold 和任务关联推导，并标 source/quality；幂等按来源唯一键，不改原余额和原分录。旧请求关联只有唯一证据才补；不能从同模型、相近时间猜任务。历史失败记录和未保存 JSON 不补造。

上线顺序：增量表/列 → 兼容写入 → 有界回填 → 与原账本校验 → 切新查询和页面。回滚通过功能开关恢复旧读入口，保留已经产生的审计与财务历史。任务受理冻结、金额精度、唯一幂等和租户谓词保持原有约束。

## 10 并行开发和 PR 纪律

同时运行三条开发线，加总控共四个进程。每条线使用独立 worktree，不在同一个分支同时改同一文件。总控独占公共路由、SQL 编号、依赖文件、共享鉴权、架构事实源、OpenAPI 与最终集成。

| 阶段 | 分支建议 | 负责人和范围 | 依赖/验收 |
|---|---|---|---|
| S0 | codex/ark-console-contract | 总控：架构修订、DTO、状态/金额字典、权限、迁移设计、验收清单 | 评审通过后冻结契约 |
| S1 A | codex/ark-assets-management | A：官方管理协议、H5、同步归属、上传校验、更新删除 | 契约测试、越权/故障/并发测试 |
| S1 B | codex/ark-pricing-matrix | B：价格矩阵、最低量、发布和报价 | 缺价拒绝、旧快照不变、预算域不重置 |
| S1 C | codex/ark-request-log-details | C：完整请求投影、正文历史副本、审计读取 | 失败请求可查、正文权限/留存/关联验证 |
| S2 A | codex/ark-assets-console | A：独立素材页面、向导、搜索预览、同步进度 | 桌面/移动端 UI 和实际接口联调 |
| S2 B1 | codex/fund-movement-ledger | B：资金操作/影响事件、回填、查询和汇总 | 资金不变量、分片、重复回调和冲正 |
| S2 B2 | codex/ark-pricing-funds-console | B：定价、流水页面、模型目录 | 四方向/四状态、金额统计、报价闭环 |
| S2 C | codex/ark-video-playground | C：日志页面、JSON 详情、新测试页契约 | 幂等、轮询不覆盖、产物和计费可查 |
| S3 | codex/ark-console-integration | 总控集成；其他线交叉审查资金与权限 | 全套门禁、迁移演练、端到端验收 |

S1 三条线可并行；各自后端契约稳定后开始对应 S2，B1/B2 由同一负责人顺序推进，避免 Ledger 并行冲突。前端可先用明确标识的 fixture 开发，最终验收必须连接真实本地后端。

以 `codex/ark-console-integration` 为本轮集成目标，基于确认的既有 PR head 创建；S0 先入集成，子分支从该共同契约提交开始，各 PR 指向集成分支。每个 PR 写明问题、行为、测试证据、依赖、迁移与回滚及未完成的真实验收。阶段通过后才合入集成；最终集成 PR 的 base 根据既有 PR 合并状态设置，避免重复包含已评审代码。不自动合入 main 或发布生产。

提交前执行仓库 vet 门禁；push 前完整 ci；涉及 web 执行 ci-all 等价门禁。分支 PR 未触发远端 CI 时补明确执行入口，不能把“没有运行”视为通过。每条完成的分支推送 GitHub 并关联 PR；不混入本地用户修改、秘密、原始参考站数据、视频二进制和临时测试文件。
