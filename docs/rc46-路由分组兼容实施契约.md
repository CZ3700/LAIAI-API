## 2. 不变量

1. 一个 Key 首期只选择一个明确路由组；不存在自动跨组选择、default 回退或跨组重试。
2. 路由组决定可用渠道/模型；计费组继续决定现有倍率。用户选组不能改变报价或账本规则。
3. 平台渠道 `owner_org_id=0` 只能加入平台组；BYOK 渠道只能加入同一 Org 的私有组。私有组只授权自己的 Org。若以后需要将平台渠道加入私有组，另行评审，G1 不隐式允许。
4. 渠道所有权校验必须保留在最终候选过滤中。绑定校验正确不等于可以删除运行时 BYOK 校验。
5. 同渠道多组绑定只增加授权关系，不复制渠道、凭据、供应商 scope、预算或并发容量。
6. 模型集合由组内已发布渠道模型派生，不持久化一份会失效的“组模型白名单”；内部 Endpoint、上游别名及 `detected_models` 不能成为授权入口。
7. 新字段缺省仅在旧写入兼容边界解释为 legacy。已经持久化的空值、未知模式或非法字段组合不得回退 legacy/latest/default。
8. G1 签发和验证仅支持 legacy。inherit_group/subset 的完整语义在 G2 全入口验收前关闭。
9. 管理变更使用事务、当前读、版本冲突检查及同事务事件；不能通过广播成功与否决定数据库授权是否生效。
10. 已受理任务的 runtime、渠道亲和与价格快照不能被分组变更重写；G1 不变更任何历史任务与金额。

## 3. 数据契约

以下为 SQL 契约，G1-A 对应 `0129_routing_groups.sql`，基于已合入的 0128 顺序扩展。使用项目既有 MySQL 版本；不得使用 GORM AutoMigrate。ID 按现有无符号整数 ID 约定实现，API 返回沿用既有 ID 编码。枚举值固定为 ASCII 小写，数据库列采用能区分大小写及尾空格的二进制 NO PAD 比较；不能只依赖 Go 字符串检查。

### 3.1 `routing_groups`

| 字段 | 类型与约束 | 语义 |
| --- | --- | --- |
| `id` | 稳定主键 | 不因重命名变化，不复用已停用 ID |
| `slug` | `VARCHAR(64)`，精确比较；仅小写字母、数字、`-`、`_` | 管理用稳定标识；唯一键 `(owner_org_id, slug)`，不是权限凭证 |
| `name` | `VARCHAR(128)`，非空 | 展示名称，可重命名；不能借同名映射计费组 |
| `description` | `VARCHAR(512)` | 简短管理说明，不接受凭据或请求内容 |
| `owner_org_id` | 非空；0 表示平台，正值表示私有 Org | 创建后不可变；无需额外 visibility 枚举表达同一事实 |
| `status` | `draft / enabled / disabled`，默认 draft | draft 不接受 Org 授权；disabled 保留关系但不提供新授权 |
| `policy_version` | `BIGINT UNSIGNED NOT NULL DEFAULT 1`，必须大于 0 | 配置 CAS；重命名、启停、绑定变更均递增 |
| `created_at / updated_at` | 与现有时间精度一致 | 元数据时间，不作为版本号 |

G1 可创建、配置并启用组及 Org 授权，但只供管理员管理，所有新模式 Key 仍禁止签发。没有“启用组即自动改变现有 Key”的路径。首次版本不提供物理删除组，只提供停用，避免破坏历史关联。

### 3.2 `channel_group_bindings`

| 字段 | 类型与约束 | 语义 |
| --- | --- | --- |
| `group_id / channel_id` | 联合主键或唯一键 | 同一关系只一行；同渠道可加入多个组 |
| `created_at / updated_at` | 时间 | 当前绑定的记录时间 |

绑定关系不再放第二套 enabled 标志：存在即绑定，解绑删除关系行，历史由同事务策略事件保留。增删都先锁 group、校验 `expected_group_version`，成功后递增 group.policy_version。同一请求重复添加/移除已达到目标的关系，在版本仍匹配时返回 `changed=false`，不增加版本；版本不匹配仍返回 409，不能掩盖并发修改。

需要索引 `(group_id, channel_id)` 与反向 `(channel_id, group_id)`。渠道被原管理接口停用/删除后，组查询不得把悬空绑定解释为可用渠道；G2 开放前必须把渠道发布、停用、删除、模型映射与目录版本事件接通，不能靠 G1 的绑定版本代替它们。

### 3.3 `org_group_grants`

| 字段 | 类型与约束 | 语义 |
| --- | --- | --- |
| `id` | 稳定主键 | 用于授权聚合事件，不因撤销/重启变化 |
| `org_id / group_id` | 唯一键 | 授权主体由服务端确定；撤销后保留此行及版本 |
| `status` | `enabled / revoked` | 只允许 enabled 参与新权限解析 |
| `grant_version` | `BIGINT UNSIGNED NOT NULL DEFAULT 1`，必须大于 0 | 状态或 default 指针改变时递增 |
| `default_slot` | 可空 `TINYINT`，仅允许 NULL 或 1 | NULL 为非默认，1 为当前 Org 默认；API 映射为 `is_default` |
| `created_at / updated_at` | 时间 | 管理记录时间 |

**多 default 的数据库约束：** `UNIQUE(org_id, default_slot)`，所有非默认值必须为 NULL，不能使用 0；同时 CHECK 限定 `default_slot IS NULL OR (default_slot=1 AND status='enabled')`。MySQL 唯一索引允许多个 NULL，因此每个 Org 最多一个有效 default 指针。不能只使用布尔字段加 UI 限制。

默认切换在同一事务中先清旧指针、再设置新指针。失败必须全回滚。撤销授权同时清除本行 default_slot。组全局停用不在锁住 group 后批量更新所有 Org：默认指针可继续指向停用组，但读取必须标记 `default_valid=false`，不自动选择其他组。重新启用时恢复的影响必须纳入管理员预览。

私有组仅能授权 `org_id=group.owner_org_id`；平台组可以显式授权多个 Org。组或 Org 不存在、Org 不可用、组不为 enabled 时拒绝新增/启用授权。重新启用授权必须重新核验这些条件，不能只修改 status。设置新 default 还要求目标 grant 为 enabled；撤销已有 grant、清除 default 允许在 Org/组已停用时执行，避免失去清理权限。

### 3.4 `api_keys` 扩展

| 字段 | SQL 写入默认 | 要求 |
| --- | --- | --- |
| `routing_group_id` | NULL | legacy 必须 NULL；inherit_group/subset 必须为有效正 ID |
| `model_access_mode` | `legacy` | 非空，合法值 `legacy / inherit_group / subset`，精确比较 |
| `policy_version` | 1 | 非空正整数；只随权限配置变化递增 |

字段必须平铺并显式写入。数据库 DEFAULT 用于旧 SQL 省略列的过渡，不用 GORM default 标签把空字符串默默改成 legacy。新增 Key 由服务层规范化缺省后显式存储 `legacy / NULL / 1`。

保留现有 `model_limits` 字符串及 legacy 精确匹配行为：空串不限，非空串按现有公有模型列表收窄，不重排、不重写历史字符串。未来 subset 的空集合表示没有权限，创建时拒绝；不能复用“空串不限”的 legacy 分支。inherit_group 必须没有额外 model_limits，携带非空值返回明确校验错误。

建议数据库 CHECK 限定模式及组 ID 组合，应用仍独立拒绝未知值，以应对未来新枚举与旧二进制交接。G1 的数据库可以表示 inherit_group/subset，但服务不签发或执行这两种 Key。不能由管理员直写数据库绕过开放门禁。

现有 `used_amount`、RPM 计数等运行时用量更新不递增 policy_version。撤销，以及后续修改 scopes、模型权限、IP、到期时间、路由策略、配置额度等授权配置时，须与配置更新原子递增。G1 至少接通当前实际存在的签发/撤销路径；不虚构尚不存在的编辑接口。

### 3.5 `routing_policy_events`

独立、低敏感的事务事件表，同时作为后续失效通知的可靠来源；不复用外发通知 Outbox。

最小字段：`id`、`aggregate_type`（group/grant/key）、`aggregate_id`、`aggregate_version`、`event_kind`、可空 `org_id/group_id/channel_id/key_id`、操作者 `actor_user_id`、`request_id`、`created_at`。aggregate_id 使用对应表的稳定主键，不用可变化的组名；Key 签发事件的操作者可以是获得现有签发权限的普通用户，不伪装成管理员。

唯一约束为 `(aggregate_type, aggregate_id, aggregate_version)`：一次聚合版本只写一个事件，多字段修改用同一事件类型与有限字段表达。default 切换改变两条 grant，分别写两个版本事件。事件不存原始请求、Key 指纹、Key 明文、凭据、渠道地址或用户素材信息；名称查询通过获授权管理接口完成。

G1 无授权缓存、不启动事件投递器，事件在同一事务内落库即可，不把“已落库”展示为“各节点已失效”。消费者接通且留存策略明确前，禁止清理策略事件。G2 实施有界、幂等的消费游标/投递状态和保留策略；后续清理也不能越过未消费水位。G2 仍以权威版本复核保障撤销，不以事件通知代替鉴权。

### 3.6 关系、索引与完整性

- 新表内部可使用非级联外键；跨 identity/relay 领域的存在性与所有权由接口在事务内核验，不以跨域 SQL JOIN 写权限，也不配置级联删除 Key、组、事件或账务记录。是否增加跨域物理外键按现有迁移约定评审，不能削弱上述应用约束。
- 组列表：`(owner_org_id,status,id)`；授权列表：`(org_id,status,group_id)` 及必要的反向 `(group_id,org_id)`；事件按自增 ID 有界读取。绑定与 default 唯一索引见上文。
- Key 的 group 索引按影响预览查询添加 `(routing_group_id,id)`；不为尚未实施的全部 G2 查询预建索引。
- `COUNT`/影响预览必须有限查询范围、独立超时与分页；大组不在写事务中全量读取 Key 或模型目录。实际索引通过真实 MySQL EXPLAIN 验证，不仅检查 DDL 中出现索引名。

## 4. 领域接口与事务锁顺序

### 4.1 包边界

新增 `core/internal/routinggroup` 负责组、绑定、grant、策略事件的仓储及规则；不得直接 import relay/video 或读取它们的私有表。宿主 server 通过接口桥接以下依赖：

- identity：按 ID 当前读并锁定 Org，新增/启用授权时校验活跃状态；Key 的创建/撤销与模式校验仍归 identity。
- channel 管理领域：按 ID 当前读并锁定 Channel，返回有限描述 `{ID, OwnerOrgID, Status}`，不返回凭据；G2 再增加发布目录快照接口。
- 事务单元：沿用同一个数据库事务，桥接实现不能偷偷另开事务或用无锁缓存代替当前读。

接口设计可采用 `LockOrganizations(ctx, tx, sortedIDs)`、`LockChannels(ctx, tx, sortedIDs)` 等显式事务方法；事务载体遵循仓库现有约定。新领域只依赖接口，宿主实现桥接，避免 G2 中 relay 引入 routinggroup 后产生循环依赖。

### 4.2 G1 管理命令的全局锁序

需要的锁按此顺序取得：

`Organization（ID 升序） → routing_groups（ID 升序） → Channel（ID 升序） → grants/bindings（稳定主键顺序） → APIKey（ID 升序） → 插入策略事件`

不需要某级锁可以跳过，但不得取得后级锁后再补前级锁。数据库外的预读只用于确定待锁 ID，锁后必须重读并验证所有权、状态与版本。发现预读结果变化时回滚并重试整个命令，不在事务中逆序补锁。

| 命令 | 必须锁定与核验 |
| --- | --- |
| 创建/修改私有组 | owner Org → group；owner 不允许后改 |
| 修改平台组 | group；不在 group 锁内遍历并锁各 Org |
| 添加/移除绑定 | 私有组先 owner Org，再 group，再 channel，再 binding；平台组 group → channel。校验 owner 组合与 expected_group_version |
| 授权/撤销 Org | 目标 Org → group → grant；核验 private owner、组状态与 expected_grant_version |
| 切换默认组 | Org → 新旧 group ID 升序 → 新旧 grants 主键顺序；锁后重验默认指针、两条版本，再清旧设新 |
| G1 签发 legacy Key | 现有 Org → 新 Key；先通过模式门禁，不锁任何 group |
| 撤销 Key | 沿用当前所有权校验，在事务内更新 Key 状态与版本并写事件；不持 Key 锁反向请求 group/Org 锁 |

此锁序仅定义 G1 管理命令，**不能直接插入已有 Task/State/receipt/ledger 锁链**。G2 在任务派发复核授权前必须单独审计现有任务锁序，明确如何获得同事务一致授权版本；未经审计不得把此表当成异步锁顺序已完成的证明。

预览仅提供信息，不替代事务内核验。未知 group/mode/version、数据库错误、缺失依赖或 CAS 冲突一律不写部分配置。业务变更、版本递增、事件插入任一失败均整体回滚。

## 5. G1 管理 API 契约

全部挂在现有管理路由和具名超级管理员鉴权下，复用已有会话、审计与管理权限规则；必须能记录实际操作者。普通 Org 管理员及 API Key 不能授予自己组权限，也不开放私有组自助管理。路径以下列逻辑路由为准，实施时核对现有 `/api/admin` 前缀，避免双重前缀。

| 方法与路径 | 请求核心 | 响应/行为 |
| --- | --- | --- |
| `GET /api/admin/routing-groups` | owner、status、游标、limit（默认 20，最大 100） | 分页组元数据与 policy_version；不展开渠道凭据 |
| `POST /api/admin/routing-groups` | slug、name、description、owner_org_id | 创建 draft、version=1；重复 owner/slug 返回 409，不静默复用 |
| `GET /api/admin/routing-groups/:id` | 无 | 元数据；绑定与 grants 另行分页 |
| `PATCH /api/admin/routing-groups/:id` | expected_version、允许修改的 name/description/status | CAS 更新；禁止变更 owner；返回新版本 |
| `GET /api/admin/routing-groups/:id/channels` | 游标、limit | 授权管理员可见的有限渠道摘要、归属与绑定信息 |
| `PUT /api/admin/routing-groups/:id/channels/:channel_id` | expected_group_version | 绑定，返回 changed 与新 group version |
| `DELETE /api/admin/routing-groups/:id/channels/:channel_id` | expected_group_version | 解绑，不删除渠道或历史任务 |
| `GET /api/admin/orgs/:org_id/routing-groups` | 游标、limit | grant_version、group_policy_version、is_default、default_valid |
| `PUT /api/admin/orgs/:org_id/routing-groups/:group_id` | expected_grant_version（首次为 0）、status | 新增/启用/撤销；撤销清默认，不支持删除授权历史 |
| `PUT /api/admin/orgs/:org_id/routing-default` | target_group_id 或 NULL、expected_current_default（ID/版本或 NULL）、expected_target_grant_version | 原子切换/清除；并发变更返回 409，不最后写入者覆盖 |

所有更新缺 expected_version 返回 400，版本不匹配返回 409 `policy_version_conflict`，不提供 `force=true`。新增 grant 的 version=0 表示“必须尚不存在”；已有 revoked 行必须提交真实版本后重启，不能借重建重置版本。

default 请求中 `expected_current_default=null` 表示调用者看到没有默认项，不是忽略当前状态。若清除默认，target 为 NULL 且不要求目标版本；若新旧是同一 grant，仍核验期望版本，返回 changed=false。

G1 管理接口响应明确 `grouped_key_issuance_enabled=false`。组状态 enabled 只表示管理员配置完成，不表示全入口组路由已上线。

影响预览与发布确认分两层：G1 变更前返回结构变化及现有绑定/grant 计数，不声称计算了全量有效模型；G2 开放 grouped Key 前必须新增与统一 resolver 一致的模型集合、受影响 Key 和动态扩权预览，并将预览版本令牌纳入发布 CAS。不能把 G1 的结构预览复用成 G2 的授权影响结论。

## 6. Key 写入与验证兼容

### 6.1 请求输入矩阵

`createKeyReq` 使用能够区分“未提供”和“显式空值”的表示。模式校验必须在开启视频权益、签发随机 Key 或写任何 Key 行之前完成；直接调用 `identity.IssueKey` 也执行同一规则。

| 输入 | G1 结果 |
| --- | --- |
| 不提供 mode/group，沿用旧字段 | 显式签发 legacy/NULL/version1，model_limits 行为不变 |
| 显式 `model_access_mode="legacy"`，未提供 group | 与上一行一致 |
| 显式空串、NULL、未知值、大小写变体或尾空格模式 | 400 `invalid_model_access_mode`，不做 Trim 后接受 |
| legacy 携带非 NULL group（含 0） | 400 `invalid_routing_group` |
| 显式 group=NULL，mode 未提供或 legacy | 按无组处理，兼容客户端可空字段 |
| 合法 inherit_group/subset 且输入组合格式正确 | 409 `group_routing_not_enabled`，零新 Key、零权益变更 |
| inherit_group 携带非空 model_limits，subset 空/缺失子集，或新模式无正 group ID | 400 结构校验错误，再无任何副作用 |

不通过忽略未知 JSON 字段来保持所谓兼容。已有输入字段保持其原语义，不要求所有旧客户端立即发送新字段。

### 6.2 持久化与鉴权

- `VerifyKey` 在签名指纹、状态及到期基础校验后，验证精确模式与字段组合；G1 只让 legacy 且 group=NULL、policy_version>0 的 Key 继续现有 Org/成员鉴权。对外返回现有安全的拒绝响应，不泄露组配置。
- `AllowsModel` 对非 legacy 或非法组合返回 false，作为深层防线；不能仅靠 HTTP 中间件挡住其他调用者。未来 G2 使用统一 resolver，不能把 inherit_group 实现为 `AllowsModel=true`。
- Key 列表返回新增只读字段；未知模式展示为不受支持，不强行显示 legacy。绝不返回 Key hash 或明文。
- Key 撤销和相关策略事件同事务完成；曾撤销的重复命令保持现有幂等语义，不重复递增版本。
- 老二进制的旧 SQL 省略三列时数据库填写 legacy/NULL/1。老二进制显式更新原字段不会清空新增列；G1 测试须证明这一点。

G1 只保证 legacy 新旧语义一致。所有节点完成 G1 前，禁止手动写入或签发 grouped Key；旧二进制忽略新字段后仍可能按空白名单执行，因此“数据库列存在”不是安全开放条件。混合阶段旧写入不会生成策略事件或递增新版本，所以新版本字段此时不能宣称覆盖全部授权变更；G2 开放要求全部活跃写入节点均理解新契约。

## 7. G2/G3 必须接续的契约

### 7.1 一个解析器，所有入口

有效模型为：

`已授权所选组内已发布渠道模型并集 ∩ Org/套餐/Key scope 允许能力 ∩ 已发布定价与接口能力 ∩ subset（仅该模式）`

解析器返回公有模型授权、组上下文与精确版本向量；候选渠道再由所属领域在相同边界下过滤与排序。`route_policy`、模型降级、同名模型重试均只能在组内执行。组不存在/disabled、grant revoked、空有效集合、空 subset、未知配置或无法确认权威版本时拒绝新准入，不 fallback 到平台池或 Org 默认组。

以下 G2 清单必须逐项接通并测试，缺一项不得开放新 Key UI：

| 入口 | 验收目标 |
| --- | --- |
| Key 选组/模型预览、鉴权目录、`/v1/models`、视频目录 | 使用相同 resolver；营销目录明确独立；预览不泄露渠道名、地址、凭据或预算 |
| 报价、Chat、Responses、图像、音频、Realtime | 同一公有模型授权；内部上游别名不能绕过 |
| Task/视频创建、所有首次派发 | 携带组及授权版本；最后发送前复核，不能只在接收时检查 |
| 模型降级与渠道 retry | 候选始终是当前授权组内且 OwnerOrgID 合法的渠道 |
| 异步查询/取消/删除与结果读取 | 用户请求验证当前 Key/scope 和原 Org 归属；内部已发送任务继续恢复与结算，不因组撤销丢失证据 |
| 日志与审计 | 记录调用时 group/version；历史未记录明确标注，不能按当前绑定反推过去 |

临时熔断、限流、容量满属于可服务状态，不删除模型授权。目录可标“暂不可用”，执行不越组。已发送任务不自动换组或重投；未发送任务仅在已有未发送证据成立时终止与释放，unknown 不得当作未发送。分组授权检查不能替代 P0-1 runtime/evidence fence。

### 7.2 版本与缓存

G1 不添加一套假完整的 catalog_version。G2 必须先覆盖所有渠道、模型发布、能力/价格发布及 Org 权益变更入口，再形成版本向量。缓存至少包含 Org/Key 身份与权限版本、group policy、grant、channel catalog、能力/价格版本及 Org 权限 epoch；不能遗漏 grant 撤销，不能仅以可撞值的版本数字当全局缓存键。

事务事件用于跨副本通知；安全撤销在新准入和派发前校验权威版本。缓存不可用或版本无法确认时暂停/拒绝新发送，内部已发请求恢复继续。不得仅以 TTL/Redis 广播成功证明撤销完成。

### 7.3 旧 Key 迁移与回退

G3 先由管理员确认平台兼容组、Org grants 与 BYOK 归属，输出旧 Key 迁移前后有效模型差分。旧非空白名单只有在确认目标组覆盖范围后迁为 subset；旧空白名单只有在显式映射明确后迁为指定组 inherit_group。禁止按计费组名称自动匹配，禁止把空列表变成“全站所有组”。

一旦允许存在 grouped Key，安全回退下限为理解模式并能拒绝它们的 G1 二进制。不得回退至忽略 group/mode 的 pre-G1 版本；关闭新建入口不会使既有 grouped Key 自动变安全。不批量改写 Key 为 legacy。

G1 的拒绝门禁不承诺 grouped Key 客户端接口可用：回退到 G1 会同时拒绝其客户查询/取消等调用，内部已发送任务恢复与结算仍须保留。G2 的正常兼容回退候选必须另外通过“关闭新准入，但保留已受理任务的客户查询/取消/删除授权和内部结算”矩阵；不能把 G1 安全拒绝能力描述成零中断回退。必要时暂停新请求并排空任务后再回退。

## 8. 迁移与发布顺序

1. 首批边界已由主控评审确认；开发前先更新架构事实源。
2. 等 P0-1 合并后 rebase 到实际 main，检查最新迁移序号、schema doctor 和 Key/Org 并发变更，正式分配新编号。
3. 新迁移 expand-only：创建组/绑定/grant/事件表、给 Key 加字段和必要索引。无历史模型清单、价格、余额、流水、任务或账单更新；不自动创建组/授权。
4. 新二进制部署后，旧 Key 继续 legacy。管理员接口可验证结构关系，但 grouped Key 签发硬关闭；混合二进制阶段仅 legacy。
5. 独立 G2 PR 接解析器、版本与全部入口，独立 G3 PR 加 UI 和管理员确认迁移；各批都有测试证据与发布说明。

迁移必须支持“表/列已建立但后续 DDL 失败”的可重放路径，遵循仓库现有迁移器。使用真实 MySQL 验证旧写入默认与已有数据完整性；不能仅用 SQLite 模拟 CHECK、NO PAD、NULL 唯一索引或并发锁。

0129 尚未发布，末尾原子 ALTER 的两个 CHECK 使用省略名称的 MySQL 约束语法，避免全 DDL 已提交但版本未记时先撞重复命名约束；六个 DDL 边界仍须真实重放验收，迁移器不全局忽略 3822，独立重复命名 CHECK 负例必须失败且不记版本。

G1 可回退旧二进制的前提是严格证明不存在 grouped Key、且没有新模式授权正在使用；保留扩展列和表，不回滚 SQL 删除数据。若无法证明，回退只允许 G1 兼容版本并拒绝新业务，不能放宽模式校验。

## 9. 测试与验收矩阵

| 类别 | 必测场景 | 通过条件 |
| --- | --- | --- |
| 迁移 | 空库升级、带历史 Key 升级、分段 DDL 中断重放 | schema 一致，重放无重复破坏 |
| 历史完整性 | Key hash/scopes/status/model_limits/quota/used_amount、Org.group_name、账本/余额/任务快照前后指纹 | 除三项新增 Key 列外原字段完全不变，无资金动作 |
| 旧写入 | 真实旧 SQL 省略新列 INSERT、旧二进制只更新旧列 | 新行 legacy/NULL/1；更新不清空新列；旧 Key 验证/模型集合等价 |
| 精确枚举 | 大小写、前后空格、NULL/空、未知模式、group=0、version=0 | 数据库和应用分别拒绝非法值；应用不依赖 CHECK 才安全 |
| Key 关闭门禁 | HTTP 和直接 IssueKey 提交 inherit/subset；请求额外字段；legacy+group | 明确错误，零新 Key、零权益副作用、零上游请求 |
| 深层鉴权 | 构造未来模式或未知持久字段，VerifyKey/AllowsModel/目录读取 | 拒绝或空授权，不落入 legacy 空列表不限分支 |
| legacy 回归 | 空 ModelLimits、非空精确列表、scopes、撤销、到期、Org/成员撤销 | 与现有授权行为一致；不改变计费倍率 |
| BYOK | 平台组绑定私有渠道、A 组绑定 B 渠道、A 私有组授权 B、归属变化竞态 | 全拒绝、零部分写入；同 Org 合法组合通过 |
| 多 default | 同一 Org 两个并发设置 default；直接 SQL 插入两个 default；撤销 default；切换第二步故障 | 至多一个；数据库唯一约束兜底；故障全回滚 |
| 锁与 CAS | 绑定/解绑与停组、grant/default 并发；过期 expected_version | 无死锁循环设计；冲突 409；无丢更新、无半条事件 |
| 事件 | 事件插入失败、重复请求、default 双 grant 更新 | 业务/版本/事件原子；无重复版本事件；不含凭据或请求正文 |
| 管理权限 | 普通用户/Org 管理员/API Key 调用管理路由；越 Org grant 操作；操作者身份缺失 | 仅具名超级管理员可管理，不靠前端隐藏；操作者可审计；不泄露组内渠道详情 |
| 性能 | 有量级的组/绑定/grant/Key 数据，分页和影响查询 EXPLAIN | 有界返回、命中适合索引，写事务不扫描全量 Key |
| G2 开放前 | 目录/报价/全部推理/Task/重试/降级/撤销与已发恢复 | 全入口同组边界；unknown 零误释放；组撤销零跨组 fallback |

测试隔离遵守现有规则：随机专属测试 schema，精确名称清理，拒绝生产/外部 DSN，不输出凭据；只用 Mock 上游，G1 不需要真实付费调用。迁移与锁测试必须给出真实 MySQL 报告，不能把 skipped 计入通过。

## 10. 分批完成定义

- 架构事实源先更新，本文的待实施项与实际实现逐项核对，不把后续 G2/G3 描述成已完成。
- G1-A 新增领域命令与迁移；数据库与服务层同时约束多 default 和 BYOK。跨域依赖采用同事务接口，暂不挂载管理 API。G1-B 补齐宿主桥接以及管理员组、绑定、grant/default API 和有界预览，才算完整 G1。
- 旧 Key 兼容字段显式落库，旧 SQL 写入兼容，HTTP 及服务层统一关闭 grouped Key，撤销版本与事件原子。
- G1-A 单测、真实 MySQL 迁移/并发测试、Key 权限回归通过；按仓库要求 `make vet` 与 `make ci` 通过。管理 API 权限和分页量级验收由 G1-B 补齐。G1 无 UI 变化，不以页面演示替代数据验收。
- PR 明确没有开放用户选组、没有接完组内执行路由、没有迁移现有 Key、没有修改价格或资金；G2/G3 开放依赖列入后续任务。

已确认的首批边界：平台渠道仅加入平台组；BYOK 仅加入同 Org 私有组；仅具名超级管理员管理；grouped Key 签发与验证硬关闭；default 唯一性由数据库约束和 Org 行锁共同保障；消费者接通且留存策略明确前不清理策略事件。这些是已确定的实施约束，不再列为用户待确认事项。G2 的完整授权解析、全入口执行及客户查询/取消回退连续性要求保持不变；任何后续扩展先补契约和测试。
