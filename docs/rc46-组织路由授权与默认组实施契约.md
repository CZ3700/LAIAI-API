# G1-B2 组织授权与默认路由组 HTTP 实施契约

2026-10-26，主控批准并先登记架构；基线main `bf311e032ce58aff23a78b38600549fad1b548ff`（PR64，CI40241312462七项全绿）。独立分支codex/rc46-routing-grants。本契约先于代码，不表示已完成验收。

## 1. 本批边界与源码事实

G1-A 已有事务化 `Service.SetGrant`、`Service.SetDefault`；G1-B1 已有具名超级管理员鉴权、主库安全摘要桥接、只读 RR 管理读服务和每实例读限流。本批补组织 grant/default 的 HTTP、管理读 DTO 和结构预览，不接入运行时路由、不新增或放开 `inherit_group` / `subset` Key，不改变渠道选择、定价、视频、资金与已有普通用户权限。

核对入口：

- `core/internal/routinggroup/service.go:295`：GrantInput、SetGrant；`service.go:368`：DefaultInput、SetDefault。
- `core/internal/routinggroup/admin_reads.go`：`read`、`adminSelect`、`organizationTx` 和 B1 结构预览。
- `core/internal/server/routing_groups_admin_gate.go`：具名 actor、全局 4 / 同 UserID 2 零等待槽、共同 1 秒业务读期限。
- `core/internal/server/routing_groups_admin_json.go`：现有递归 token 校验拒绝所有 JSON null，不可直接用于清除默认组。
- `migrations/0129_routing_groups.sql`：组织授权唯一键 `(org_id,group_id)`、默认槽唯一键 `(org_id,default_slot)`，`default_slot=1` 必须为 enabled 授权。

现有行为应保留：

1. 新授权仅允许 `enabled` 且 expected=0，创建版本 1；已存在的授权使用正版本 CAS。新增 revoked 不创建“占位授权”，返回 404。已有授权 expected=0 冲突。
2. 启用授权要求 Org active、group enabled 且 group 为平台组或该 Org 私有组；撤销允许 Org/group inactive。撤销当前默认授权会在同一条 grant 变更中清空默认槽、版本 +1、写一条 `grant_revoked` 事件，不额外伪造 `default_cleared` 事件。重新启用不恢复默认槽。
3. SetDefault 在同一事务中锁 Org，核对实际当前指针，按 group ID 升序锁组，再按 grant ID 升序锁授权，核验当前与目标授权版本，先清旧再设新。切换两侧各版本 +1、各一条事件；设首个或清除只变一侧；准确重复配置不写事件。
4. 当前指针未变但当前 grant 版本变了，也必须 409；从无默认设置时，显式期望空指针不可解释为“不检查”。这是当前状态 CAS，不是覆盖 Org 历史的全局 revision：无默认→设置→清除的 ABA 不由额外 epoch 检测，本批不声称具备该能力。
5. 对另一个 Org 的私有组，现有 `lockGrantGroup` 在带归属谓词的读取中返回 `ErrNotFound`，HTTP 为 404；本批不额外查出对象再改成 403。Inactive 为 403。只有资源可访问且满足相关前置条件时才进入对应 CAS，错误优先级沿领域实现，不承诺所有同时发生的错误一律 409。

## 2. 身份与路由

挂在现有 `/api/admin` superadmin 中间件之后，所有新入口再使用 `requireNamedRoutingAdmin`。只接受主库核验的活跃、具名 superadmin 会话。共享 root token、API Key、普通用户、Org 管理员、平台 admin、停用 superadmin 均不得操作；混合 root token 和会话继续拒绝。actor 与 request ID 仍由服务器提供，不接受 Body 中的替代值。

| 方法与外部路径 | 用途 |
| --- | --- |
| GET `/api/admin/orgs/:id/routing-groups` | 现有组织授权列表，包含 revoked，支持 status/cursor/limit |
| PUT `/api/admin/orgs/:id/routing-groups/:group_id` | 授权、撤销、重新启用，按 grant CAS |
| GET `/api/admin/orgs/:id/routing-default` | 当前默认指针及其配置有效性 |
| PUT `/api/admin/orgs/:id/routing-default` | 设置、切换、清除默认组，核验完整指针 CAS |
| POST `/api/admin/orgs/:id/routing-groups/:group_id/impact-preview` | 对同一 grant 命令做只读结构预览 |
| POST `/api/admin/orgs/:id/routing-default/impact-preview` | 对同一 default 命令做只读结构预览 |

路径中的 `:id` 是目标 OrgID，必须正整数；不是当前会话所属组织，也不得从 Body 覆盖。实际 Gin 注册继续用已有 `/orgs/:id/...` 的参数名，避免与现有定价分组路由的 `:id` 通配符冲突。禁止复用或改变 `/orgs/:id/group`（那是计费分组）。所有成功响应附 `grouped_key_issuance_enabled:false`，继续 `Cache-Control: private, no-store` 和 `X-Request-Id`。

不另加迁移；先使用已有 grant 索引验证查询计划。实施时若事实证明索引不足，再由主控单独批准，不能在本草稿占迁移号。

## 3. 明确请求与响应 DTO

### 3.1 授权命令

PUT 与对应 preview 使用同一 Body：

```json
{"expected_grant_version":0,"status":"enabled"}
```

`expected_grant_version` 必须出现，允许整数 0（仅“期望尚无此授权”）；`status` 必须出现，只接受 `enabled` / `revoked`。不接受 null、浮点、负数、科学计数法、字符串数字、溢出、未知字段或客户端 org/group/actor/default。路径决定 Org/group。

写入成功统一 200，不依赖之后的 GET：

```json
{
  "org_id":55,
  "grant":{"id":8,"org_id":55,"group_id":12,"status":"enabled","grant_version":1,"is_default":false},
  "changed":true,
  "grouped_key_issuance_enabled":false
}
```

grant 直接来自 `SetGrant` 的事务结果，允许补 created_at/updated_at，但不返回 GORM model 或未经白名单的 group/channel/Org 数据。相同状态且版本一致为 changed=false；仍执行领域前置和 CAS，不因“看起来无变化”跳过校验。

### 3.2 默认组命令与 null

设首个默认：

```json
{"target_group_id":12,"expected_current_default":null,"expected_target_grant_version":1}
```

从 A 切到 B：

```json
{"target_group_id":13,"expected_current_default":{"group_id":12,"grant_version":2},"expected_target_grant_version":1}
```

清除默认：

```json
{"target_group_id":null,"expected_current_default":{"group_id":12,"grant_version":2}}
```

准确无操作（期望无默认且目标也为空）：

```json
{"target_group_id":null,"expected_current_default":null}
```

固定规则：

| 字段 | 缺少 | 显式 null | 有值 |
| --- | --- | --- | --- |
| target_group_id | 400 | 明确清除 | 正整数目标 group ID |
| expected_current_default | 400 | 明确期望无默认 | 仅 `{group_id,grant_version}`，两者必填正整数 |
| expected_target_grant_version | 目标非空时 400；目标为空时应省略 | 始终 400 | 仅目标非空时允许正整数；清除时传任何值均 400 |

当前与目标相同也必须提交当前/目标两份版本，并都与实际版本一致；不能以相同 ID 省略 CAS。若两份正整数不同，进入领域校验后 409，不把其中一个覆盖另一个。当前有默认而请求期望 null 为 409，不自动推断实际指针。缺字段绝不可自动转成 null。

映射到现有 `DefaultInput`：`OrgID=id`，`ExpectedGroupID/ExpectedCurrentVersion` 来自 expected_current_default；`GroupID` 来自 target；`ExpectedTargetVersion` 来自非空目标。Audit 来自会话。清除时两个不用的版本保持 0，但只有严格 presence 校验完成后才构造领域输入。

最小写响应沿用现有 SetDefault 的 bool 返回值，作为命令回执：

```json
{"org_id":55,"applied_target_group_id":13,"changed":true,"grouped_key_issuance_enabled":false}
```

`applied_target_group_id` 是本次事务提交的目标（可 null），不是响应瞬间“仍然当前”的宣称。需要最新版本时客户端显式 GET default/list。不得在提交后附加一个强制读取，把读取超时报告成整个 PUT 503；不得按请求版本在宿主推算并声称数据库最新版本。这样不必修改已有 SetDefault 方法签名或重构其事务。

### 3.3 授权列表和默认快照

GET 授权列表只接受 `status=enabled|revoked`（可省略）、`cursor`（可省略/0）、`limit`（默认20，1..100）。游标明确定义为 **group_id**，SQL `org_id=? AND group_id>? ORDER BY group_id ASC LIMIT limit+1`，status 给定时再固定筛选。适配已有 `(org_id,group_id)` / `(org_id,status,group_id)` 索引，无 OFFSET、无全量 COUNT，不把 grant.id 和 group_id 游标混用。

响应：`organization:{id,active}`，`items:[]`，`next_cursor`（无更多时0），`has_more`，`current_default`，以及关闭 grouped Key 的标志。每项：

```json
{
  "grant":{"id":8,"org_id":55,"group_id":12,"status":"enabled","grant_version":2,"is_default":true},
  "group":{"id":12,"owner_org_id":0,"slug":"public-video","name":"公开视频","status":"enabled","policy_version":3},
  "group_exists":true,
  "ownership_valid":true,
  "configuration_valid":true
}
```

这是现有授权表，不自动枚举未授权组；给新授权选组复用 B1 group 列表。`configuration_valid` 只表示 active Org + 存在且 enabled group + 合法归属 + enabled grant，不表示模型、渠道或 Key 的实际调用权限。没有绑定渠道仍可配置授权，不能误用 grouped Key 已可用的文案。

GET default 返回相同 organization 和 `current_default`。无默认时 current_default=null；有默认时：

```json
{
  "group_id":12,
  "grant_version":2,
  "group_policy_version":3,
  "default_valid":true,
  "invalid_reasons":[]
}
```

`invalid_reasons` 使用固定枚举 `org_inactive/group_missing/group_inactive/ownership_mismatch/grant_inactive`，不反射 SQL；group 缺失时 group_policy_version=null，不能伪造 0 为有效版本。停用组保留当前指针，default_valid=false；恢复组后再查询可恢复 true，不自动改 grant。列表中的默认快照与分页/filter 独立，即默认 grant 不在当前页或 status=revoked 筛选也不能被误报为空。

允许具名 superadmin 读取 inactive Org 的配置以便清理；不存在 Org 404。历史脏关系可以用 group=null、ownership_valid=false 显示，不删除、不修复；强制修改损坏归属/缺失组不是本批功能，写领域继续拒绝。

## 4. 严格 JSON 的最小扩展

不能把 `routingAdminJSONValue` 当前 `token==nil` 检查全局删除。建议抽一个私有 path-aware 校验器，现有 `routingAdminJSON` 仍以空 null 白名单调用，保持 B1 原行为；新 default 专用入口仅允许顶层路径 `/target_group_id` 和 `/expected_current_default` 的 null。grant 仍走原严格入口。

先递归 token 扫描保留重复键、嵌套重复、深度 8、UTF-8、16KiB、唯一顶层对象、无尾随 JSON 等约束；再 exact-case 字段白名单；最后用 RawMessage map 的键存在性解析三态。不要直接用 `*uint64` 区分 omitted/null，因为两者都会成为 nil。不得允许同名字段在数组/嵌套路径里的 null，不得因嵌套对象缺字段而退化成空期望。URL 参数继续拒绝未知/重复与空非法值；写接口不接受任何 query。

Body 语法错误 400；资源未找到或带归属谓词不可见 404；CAS 409 `policy_version_conflict`；Inactive 403；读 gate 满 429；业务数据库/取消/期限失败为安全 503。沿用 B1 静态错误返回和局部 Logger.Discard。身份中间件故障的已有 401 行为不在本批改变。

## 5. 管理读与结构预览实现边界

新增 `routinggroup/admin_org_reads.go`，只在领域拥有的组/授权表上查询；Org active 仍调用 `OrganizationReader` 同一 tx 的安全摘要。复用 `AdminReadService.read/adminSelect/organizationTx`，禁止在 server 裸 SQL，禁止用 UPDATE 锁充当 RR 摘要。

建议冻结的领域 API：

```go
type OrgGrantFilter struct { Status string }
type AdminOrgGrant struct { Grant Grant; Group *Group; GroupExists, OwnershipValid, ConfigurationValid bool }
type DefaultView struct { GroupID, GrantVersion uint64; GroupPolicyVersion *uint64; Valid bool; InvalidReasons []string }
type OrgGrantPage struct { Organization Organization; Items []AdminOrgGrant; Default *DefaultView; NextCursor uint64; HasMore bool }
type OrgDefaultView struct { Organization Organization; Default *DefaultView }

func (*AdminReadService) ListOrgGrants(context.Context, uint64, OrgGrantFilter, Page) (OrgGrantPage, error)
func (*AdminReadService) GetOrgDefault(context.Context, uint64) (OrgDefaultView, error)
```

grant/default preview 分别接收去掉 Audit 的同形只读输入，返回观察的 grant/当前指针/涉及 group 版本、规范化命令、changed、最多两项拟变更。可以复用私有纯校验函数保证与 SetGrant/SetDefault 的归属、active、CAS、no-op 含义一致，但不能调用写服务再回滚来实现 preview。

每次新 GET/POST preview 与 **所有 B1 读取共用** `s.routingGroupReads`：每实例总4、同具名 UserID2、零等待429；Org 改变不产生新主体桶。只有一个外层 gate 和共同1秒ctx，不能在内部多次获取 gate 或重置期限。鉴权时间依旧另计。每个 SELECT 的ctx/hint<=200ms且不超过剩余期限；同一个主库只读 RR 事务完成所有关系及 Org 摘要，失败丢弃全部结果。

列表最多读取101条 grant，只为返回的100条构建 DTO；分页组和可能不在页内的默认组 ID 去重排序，分批每批<=100（最多两批），保持<=5次业务 SELECT 的固定上界：Org、grant页、当前默认grant、group摘要一至两批。GET default/preview 只需单Org、至多两条grant和两组，不能每行 N+1。实际SQL数量通过验收记录后锁定；辅助查询增量必须显式审查。

preview 成功固定：

```json
{
  "preview_kind":"structure_only",
  "org_id":55,
  "changed":true,
  "change":{"target_group_id":13,"expected_current_default":{"group_id":12,"grant_version":2},"expected_target_grant_version":1},
  "observed_current_default":{"group_id":12,"grant_version":2},
  "observed_grants":[],
  "affected_grants":[],
  "effective_model_impact_available":false,
  "grouped_key_issuance_enabled":false
}
```

`observed_grants` 为受影响现有授权安全 DTO，最多2；新授权用明确的 `exists:false` 描述，不分配虚拟数据库 ID。`affected_grants` 逐项描述拟创建/启用/撤销/default清除/default设置以及拟版本增量；新 grant 的未来 id 不可预测，留空/不提供。对撤销当前默认授权明确展示默认清除。对准确 no-op 返回 changed=false/空变更。无效命令与写域相同拒绝，不返回“可提交”。

这些是配置结构变化，不枚举 Key、有效模型、费用影响或节点缓存状态；不用再做全组织计数，所以不会借 preview 扫描所有授权。若未来增加影响计数，须沿用B1的1000+1有界下界协议，不能现在返回虚假精确数量。preview 没有可复用授权票据或随机 Key；最终提交重新锁定并检验，观察到的 group版本只作说明，不悄悄变成缺省忽略的额外 CAS 字段。

## 6. 写入锁序与持久性

新 HTTP 直接调用既有 Service，不先读取版本来替用户填CAS，不“读取后合并”客户端遗漏的默认字段。

- SetGrant：Org current UPDATE锁 → 合法归属group UPDATE锁 → grant UPDATE锁 → grant变更/事件。未知 Org/归属/状态拒绝无写入。
- SetDefault：Org UPDATE锁 → 发现当前指针 → 旧/新组ID升序UPDATE锁 → grant稳定ID升序锁并重查 → 清旧/设新/事件同事务；数据库唯一默认槽继续兜底。不能为了HTTP响应调整锁序。
- 两种写命令仍共用现有5秒事务期限；读gate只管理读/preview，不能以新增独立gate绕开B1总容量。资金/Key/Task/渠道不参与写事务。
- 默认切换失败（包括第二侧事件写入失败）整笔回滚，不能留下“旧默认已清、新默认未设”。不删除历史事件；授予/撤销/default操作不改变 group.policy_version。
- CAS 是乐观并发，不是重试免校验。网络丢回执后客户端先GET，不用 stale expected 盲目重试。无 force 模式。写结果不能拼接后提交的另一事务读结果伪装同快照。

## 8. 独立 MySQL 验收矩阵

测试从 `ARK_TEST_MYSQL_DSN` 且 database严格为 `ark_test` 派生唯一 `ark_test_rgadmin_...` 私库，实际 tracked migrations，精确schema清理。复用已有fixture中同pool但独立GORM callback registry的管理句柄，避免与relay后台元数据读取竞态；不复制DDL、不AutoMigrate、不动外部库。

1. **真实HTTP全链路**：平台组+同Org私有组→enable→expected0 grant v1→设default v2→切到B（A/B各+1）→revoke B自动清空→reenable不复原default→显式重新设置→清除；逐步核对事件aggregate版本和 actor/requestID，预览全过程0写入。
2. **身份与Org边界**：superadmin跨目标Org正确；普通/Orgadmin/平台admin/root/APIKey/混合root凭据全部拒绝。外Org私有组404，平台组可分别授给A/B；Body注入org/owner/actor失败。inactive Org/group禁启用/设置，但允许现有grant撤销、现有default清除和只读诊断。
3. **grant CAS**：expected0新建正控；缺/null400；已有expected0和不存在expected>0为409；新建revoked404；相同状态准确版本changed=false且无事件。两连接真实HTTP同时expected0仅一200一409，表仅一行事件；两次同旧正版本变更也仅一胜。
