# 全站显示币种切换实施计划

> 制定日期：2026-10-22  
> 适用范围：LAIAI Console、公开模型页面及管理后台只读金额展示  
> 目标币种：USD、CNY

## 1. 项目背景

当前系统采用 USD 作为全站计价、账本和结算事实单位，并已配置全局 `cny_per_usd` 汇率用于部分人民币支付场景。客户希望用户能够自行选择全站显示币种：

- 选择 USD 时按美元显示；
- 选择 CNY 时，系统按平台配置的固定汇率自动折算并以人民币显示；
- 用户的显示选择应在全站生效，并在刷新、重新登录和切换组织后继续保留。

## 2. 推荐方案

采用“USD 账本不变 + 全局固定汇率 + 用户级显示币种”的方案：

```text
USD 账本/API ──→ 统一金额展示层 ──→ $ USD
                      │
        用户偏好 + 全局 cny_per_usd
                      └──────────→ ¥ CNY
```

人民币展示公式：

```text
CNY 展示金额 = USD 原始金额 × cny_per_usd
```

### 2.1 核心原则

1. 内部计价、账本、余额、模型价格、额度、API、CSV 和 Webhook 继续使用 USD。
2. CNY 仅作为展示层折算结果，不回写账本，不参与 hold、capture、release 等资金动作。
3. 全局固定汇率继续由平台超级管理员维护。
4. 显示币种属于用户个人偏好，不属于组织配置；用户切换组织时偏好保持不变。
5. 所有金额从 USD 原值单向换算，禁止对已经是 CNY 的金额再次换算。
6. 所有金额计算使用十进制定点运算，禁止使用浮点数参与资金换算。

该方案与现有架构中“内部 USD 单币种、展示层做多币种换算”的设计保持一致。

## 3. 本期范围

### 3.1 纳入范围

- 用户设置中的显示币种选择；
- Console 全部只读金额；

- 管理后台只读财务看板；
- USD/CNY 动态单位和多语言文案。

### 3.2 本期不改变的内容

- 数据库账本及所有资金字段仍为 USD；
- API、OpenAPI、CSV、Webhook 中的 `*_usd` 字段保持不变；
- 模型定价、授信、额度、余额预警等写入接口仍按 USD 提交；
- 充值订单的 `pay_amount/pay_currency` 按实际支付币种展示；
- Ark 等供应商原生 CNY 预算继续按 CNY 展示；
- 本期不支持用户自定义汇率。

对于仍以 USD 输入的表单，可在输入框旁显示 CNY 参考值，但提交 payload 和后端契约不变。

## 5. 后端实施方案

### 5.1 用户显示币种字段

新增版本化迁移：

```text
migrations/0126_user_display_currency.sql（实施时 main 已到 0125，顺延编号）
```

建议字段：

```sql
ALTER TABLE users
ADD COLUMN display_currency CHAR(3) NOT NULL DEFAULT 'USD';
```

应用层仅允许以下值：

- `USD`
- `CNY`

所有历史用户通过数据库默认值自动使用 USD，确保上线后现有行为不发生变化。

同步更新：

- `core/internal/identity/identity.go` 中的 `User` 模型；
- 测试使用的 SQLite `users` 表镜像；
- 用户相关 API DTO 和测试夹具。

### 5.2 用户偏好接口

调整 `GET /api/me`，增加：

```json
{
  "display_currency": "USD"
}
```

建议新增独立接口：

```http
PUT /api/me/preferences
Content-Type: application/json

{
  "display_currency": "CNY"
}
```

接口要求：

- 仅登录且状态正常的用户可调用；
- 只能修改当前登录用户；
- 不接受客户端传入 `user_id`；
- 严格校验为 `USD` 或 `CNY`；
- 不写入 JWT，修改后无需重新登录；
- 切换组织不改变显示币种。

不建议直接无条件扩展现有 `PATCH /api/me`，因为当前接口只处理显示名；如果复用，必须将字段改为可选指针并按实际传入字段更新，避免只提交币种时清空显示名。

### 5.3 收口全局汇率

当前 `cny_per_usd` 在公开配置、支付方式接口和 EPay 下单中存在不同的默认处理方式。应抽出唯一的有效汇率函数，例如：

```go
effectiveCNYPerUSD() (decimal.Decimal, string)
```

该函数应：

- 读取 `ext_settings.cny_per_usd`；
- 只接受正十进制字符串；
- 最多允许 8 位小数；
- 未配置时统一使用 `7.3`；
- 返回规范化的十进制字符串；
- 配置损坏时记录告警并使用安全默认值。

以下位置必须使用同一函数：

- `GET /api/config`；
- `GET /api/payment/methods`；
- EPay 创建充值订单；
- 后续所有 CNY 展示配置下发。

### 5.4 汇率配置安全

后台保存汇率时应：

- 拒绝空白以外的非法字符串；
- 拒绝零值和负数；
- 拒绝超过精度限制的值；
- 根据运营策略限制明显不合理的数值范围；
- 在审计日志中记录旧值和新值；
- 将后台文案改为“全站展示及 EPay 结算固定汇率”；
- 明确提示修改汇率会影响未来 EPay 实付金额及所有人民币折算展示。

## 6. 前端实施方案

### 6.1 全局币种状态

建议新增：

```text
web/src/stores/currency.ts
```

主要状态：

```ts
displayCurrency: 'USD' | 'CNY'
cnyPerUsd: string
ready: boolean
```

初始化流程：

1. 从 `/api/config` 读取有效固定汇率；
2. 登录用户从 `/api/me` 读取显示币种；
3. 未登录用户默认 USD，可读取匿名本地偏好；
4. 登录用户以服务端偏好为准；
5. 本地缓存按用户 ID 隔离，避免共享浏览器串号；
6. 汇率或用户信息尚未加载完成时使用骨架状态，避免先显示 USD 后突然跳为 CNY。

### 6.2 统一金额格式化

重构：

```text
web/src/lib/money.ts
```

建议提供：

```ts
convertUsdToDisplay(...)
formatUsdForDisplay(...)
formatNativeMoney(...)
displayCurrencyCode(...)
displayCurrencySymbol(...)
```

约束：

- 使用十进制定点库或等价的字符串十进制计算；
- 不再使用分散的 `Number(...).toFixed()` 做金额换算；
- 排序、筛选和业务判断继续使用 USD 原始值；
- 图表可使用 Number 计算几何尺寸，但 Tooltip 必须使用统一金额格式化器；
- 对非法金额或非法汇率 fail-safe 回 USD，不显示 `NaN` 或 `Infinity`。

### 6.3 显示精度

建议按业务场景处理：

| 场景 | 建议显示精度 |
|---|---:|
| 余额、充值、月度账单 | 2 位小数 |
| 调用成本、账本微额变动 | 2–4 位小数 |
| 模型单价、极小额调用成本 | 4–6 位小数 |

同时处理：

- 正负号；
- 负零；
- 零值；
- 极小金额；
- 超大金额；
- CNY 符号与币种代码的可读性。

### 6.4 设置入口

在用户设置页增加“显示币种”区块：

```text
显示币种
○ 美元（USD）
○ 人民币（CNY）
```

当选择 CNY 时显示：

```text
人民币金额按平台固定汇率折算：1 USD = ¥7.30。
账本、计费和接口仍以 USD 为准。
```

保存成功后更新全局 Store，使当前页面和后续路由立即响应，无需刷新。

## 9. 验收标准

1. 新老用户默认显示 USD，现有用户上线后无视觉和业务变化。
2. 用户可在设置页选择 USD 或 CNY。
3. 两个用户在同一组织可使用不同显示币种。
4. 选择 CNY 后，全部纳入范围的页面使用同一个固定汇率。
5. 切换后无需刷新即可更新当前页面。
6. 刷新、重新登录和切换组织后偏好仍然有效。
7. 表头、金额符号和多语言文案保持一致，不出现“金额为人民币、标题仍写 USD”的情况。
8. 余额、账本、模型价格、额度、调用成本和 CSV 原始 USD 数据完全不变。
9. EPay 实付金额与全局汇率一致，显示偏好不影响支付订单。
10. 实际支付币种和 Ark 原生 CNY 不发生二次换算。
11. 非法汇率无法保存，不出现 `NaN`、`Infinity` 或错误的零金额。
12. 全量 CI、迁移冒烟和账本漂移检查通过。

## 10. 灰度上线方案

建议增加应用侧开关：

```text
currency_display_enabled=false
```

上线阶段：

1. 发布数据库迁移、用户偏好 API 和前端基础能力，开关保持关闭；
2. 在测试环境开启并完成完整验收；
3. 生产环境仅对内部账号或组织开放，观察至少 24 小时；
4. 按稳定用户或组织哈希依次放量 5%、25%、100%；
5. 每阶段至少观察 24 小时；
6. 全量后保留总开关至少一个发布周期。

每阶段观察：

- `/api/me` 和偏好接口错误率；
- `/api/config` 获取失败率；
- 前端异常率；
- 页面 CNY 与 API USD 抽样换算一致性；
- EPay 金额或币种不匹配数量；
- 充值成功率；
- 账本漂移；
- API Key 额度、hold 和 capture 结果。

## 11. 回滚方案

发生问题时：

1. 关闭 `currency_display_enabled`；
2. 前端统一恢复 USD 展示；
3. 必要时回退前端静态版本；
4. 保留 `users.display_currency` 字段及用户已保存的偏好；
5. 不删除迁移，不修改账本，不重算历史交易；
6. EPay 继续使用服务端统一有效汇率。

由于项目迁移体系只提供向前迁移，数据库字段不作为本功能的常规回滚对象。

## 12. 需要提前确认的产品决策

本计划默认：历史 USD 流水的 CNY 金额使用“当前固定汇率”实时换算。因此管理员修改汇率后，历史页面中的 CNY 展示也会随之变化，但原始 USD 金额不会变化。

如果客户要求历史账单中的人民币金额永远不变，则需要扩展为“汇率版本 + 生效时间 + 交易时汇率快照”方案，并在订单、账单或发票层保存 FX 快照。该需求预计额外增加 1–2 个开发/测试人日，且应单独评审账务和审计口径。

## 13. 本次实现与发布操作

- 正式迁移采用 `0126_user_display_currency.sql`，适配实施时 main 的 0125 基线。本地 Ark 管理扩展使用完整迁移文件名识别，保留其已有迁移。
- `GET /api/me` 返回保存的 `display_currency` 和当前会话的 `currency_display_available`。偏好接口严格拒绝未知字段、非 USD/CNY、未登录或禁用用户；不修改显示名、JWT 或组织配置。
- 固定汇率允许 `0.01–100`、最多 8 位小数，拒绝指数格式。空白归一为空配置并使用 7.3。后台设置整批校验和事务保存，汇率/灰度变更的旧值、新值与设置在同一事务审计。该范围是配置误填保护，并非实时市场汇率判断。
- 前端使用 BigInt 字符串十进制运算，无新增依赖。半入舍入；默认大于等于 1 保留两位，小额四位，极小金额六位，低于最小显示精度用 `<最小单位`，非法金额用 `—`。尚未加载用 `…`。充值实付、供应商原生人民币及写入表单保留原币种。
- 不缓存个人偏好到浏览器：登录后直接以服务端为准。会话变化清空展示上下文，过期请求和保存回执不能覆盖新账号。窗口重新获得焦点和每 60 秒刷新配置；关闭开关在下一次刷新生效，用户偏好保留。
- 设置入口：个人设置 → 显示币种；仅灰度命中的用户显示。管理入口：后台 → 支付 → 全局结算设置，固定汇率和灰度设置一并保存。
- 灰度设置：`currency_display_enabled=false` 默认关闭；`currency_display_percent=0` 默认不随机开放；`currency_display_user_ids` / `currency_display_org_ids` 为逗号分隔的正整数白名单。百分比仅允许 0、5、25、100，以 `FNV-1a("display-currency-v1:" + userID) % 100` 稳定分桶。白名单与百分比取并集，总开关优先。
- 未登录的公开模型页默认 USD；已登录浏览公开模型页继承个人偏好。请求/响应 JSON、导出 CSV、文档示例保留原始 USD。价格编辑器中的 USD 售价、CNY 成本和历史 FX 快照属于写入契约，明确保留原单位。

### 验证与灰度记录要求
