## 3. Stage和reader不能简化的顺序

1. Stage确认受控factory标记、固定purpose/schema及prepared不可变身份，使用原业务事务内savepoint。**当前旧StageTx的重复行读取是普通RR Take**；新execution Stage必须对correlation命中的原metadata当前锁读，不能照搬旧快照分支。
2. INSERT/冲突等待、原metadata与staging一致性检查完成后，才读主库clock；replay也必须过这一步。新生成的随机密文若撞旧correlation仍冲突，不能覆盖旧行；重复同一prepared只能读回原同字节事实。
3. 过期或clock失败回滚本次savepoint；C必须返回错误，令reserve/claim/EA同一外层事务回滚。不能因调用者捕获error而留下半个metadata/staging对，也不能重写历史CreatedAt/ExpiresAt。
4. Window为精确metadata当前 `FOR SHARE` 读→授权用途/schema/correlation→当前生命周期→DBclock。单tx不会另占连接；短reader前后数据库阶段不跨Blob/AES持锁。
5. reader现有 `deny()` 会让审计失败覆盖原错误；新execution reader必须保留身份/未知格式/authority错误优先级。缺成功审计永不返回明文，且末段在可能等待的成功审计写之后再clock；失败回滚该“成功”审计，清空plain后返回安全拒绝。不能仅复用旧host-now读流程并换两行time来源。
6. metadata-only校验与window分开。身份合法且已过期是允许进入原合法NotSent reducer的候选事实；**expiry绝不是退款许可**。未知身份/clock故障优先返回。body成功读出后仍需原最后COUNT的DB时间比较，不能把Window当缓存许可。

## 7. 交接结论

终稿已转为正式契约，现按冻结基线及文件归属实施。此次补齐的实施落点是：A必须拥有 `video_types.go` 的私有来源标记；B独占原Purge测试迁移；C必须覆盖CancelLocally与shared create NotSent reducer，而不误将已发任务GET结算接到input TTL；Stage replay当前读、末段审计后的clock和四家族真实binary门禁保持不可省略。初始无DDL决定中的候选索引部分，已由实施契约第10节批准的0132替代；分组Key及Blob uploader仍不因此开放。
