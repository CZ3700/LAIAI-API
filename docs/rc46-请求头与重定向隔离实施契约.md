## 1. 边界与依据

官方 Ark 已通过新请求构造固定 Authorization，并禁止全部 redirect。现有 generic guarded 客户端只在跨 Host 时删除四种认证头；通用 override 允许任意字段展开 credential，因此自定义头不能靠黑名单保护。已有本机合成凭据 probe 证明自定义头跨 hostname 泄漏及同 Host HTTPS→HTTP 降级携带认证头；这不是官方 Ark 泄漏结论。

本片修 generic 客户端隔离，补官方固定头黑盒。没有 DDL、凭据接管、runtime/HMAC 格式、worker/inbox、价格、FX、账务或生产开关变化。历史任务继续使用原凭据及账务快照；同账号/项目接管仍需可信证明，不能由管理员填写 scope 或一次 GET200 替代。

## 2. 两种明确策略

### 2.1 带凭据 API、OAuth 与 webhook

- origin 是 `(scheme, hostname, effective port)`；DNS hostname 大小写可归一，HTTP/HTTPS 缺省端口分别80/443。显式端口须纯十进制、1..65535，拒绝空端口和非法 authority。IPv6 literal 用 IP 解析归一，其 zone 保留精确大小写，不把 zone 当 DNS 小写化。主机尾点、别名不做等价扩展。
- 只跟随同 origin；所有 HTTPS→HTTP、redirect userinfo、非 HTTP(S)/缺 host/非法 port 拒绝。POST 307/308 的正文不能到另一 origin；同 origin 仍沿 Go 的方法转换语义。
- 拒绝与达到原守卫上限均返回 `http.ErrUseLastResponse`，保留原3xx给既有调用者，不新增带 URL 的错误或业务重试。`len(via)>=5` 保持原守卫的精确次数语义：初始请求计入 via，最多五个实际请求。
- 新建客户端 Jar 为 nil。不改原首跳 HTTP/private/代理信任规则，不以此宣称全站 SSRF 或 WebSocket 保护。

### 2.2 媒体下载

- 仅初始及全部 via 请求都是 GET/HEAD，且无 body，才可跟随跨 origin。POST→303 GET 不能借媒体模式放行。
- 在第一次跨 origin 后，依据完整 via 链判断已跨站；每一跳都新建空 Header，清 `req.Host`，绝不从初始 Header 恢复。A→B→B、A→B→A 均无认证、Cookie、Proxy-Authorization、Referer 或任意自定义字段。没有任意值白名单，也不复制 Accept/User-Agent 中可能藏的 credential。
- 尚未跨站的同 origin 媒体请求保留初始 provider 头。保留 provider 明确给出的 Location 签名 query；不把旧签名 URL 作为 Referer 发给新站。此范围不改变 provider 指定的首跳媒体 URI 信任边界。
- 每跳同样拒绝 HTTPS→HTTP、userinfo、非法 URL；保留原拨号 IP/metadata 守卫、private 设置和五请求上限。客户端 Jar 必须为 nil：Go 会在 CheckRedirect 后由 Jar 添加 Cookie。
- 只允许值复制 Client 来派生媒体模式并共享只读 Transport；不能原地修改缓存 Client/Transport/TLS/Proxy。每条链状态由 via 推导，不能存在共享可变“已跨站”标志。

## 3. 固定落点

relay 新 `redirect_policy.go` 负责纯 origin/策略及 `NewUpstreamClient(timeout)`。`NewGuardedClient` 默认采用 API 策略，新增 `NewGuardedMediaClient`。relay 默认、proxy、advanced/BYOK guarded client 以及 GCP token client 全接 API；task 默认 Client 同样接 API。notify 现有 guarded 构造随之采用 API。

task 的 HandleContent/HandleMJImage 两处改用 guarded-media，覆盖直链、Sora/Veo StreamResult 和 MJ 图；Replicate 仅图片下载 client 改为共享 Transport 的媒体副本，prediction poll 保持 API。videoartifact/videoasset 既有全禁 redirect 不放宽。generic HeaderOverride 验证与认证构造不改。

Ark execute 保持全禁 redirect，仅将复制的 Client.Jar 清空，保证意外传入 Jar 不增加 Cookie，不修改共享 client。POST/GET/DELETE 和交付 Query 不接 arbitrary override、不从入站 Header 继承、不自动切活动凭据、不重试 POST。

## 4. 验收

使用真实 Go Client.Do redirect engine、本机 HTTP/TLS Mock、合成凭据、专属 CA/SAN；不使用 InsecureSkipVerify，不访问官方。有限矩阵至少包括：

1. 官方三个方法×五种 redirect 状态均仅首跳且 OutcomeUnknown；固定 Bearer/Content-Type、无 Cookie/Idempotency-Key/GetBody，两个 credential 并发不串线，原 Client/Jar/Transport 不被改写。
2. API 同 origin 成功正控；host/port/subdomain/降级/userinfo 等拒绝；POST body 不跨 origin。真实 default/proxy/guarded/BYOK/task/GCP/notify 工厂接线不能只由 callback 单测代替。
3. 媒体 A→B→B/A 每一跳不带任何自定义秘密头；返回真实媒体字节与签名 query 正控，首跳认证仍正常；POST、降级、userinfo、跳转上限拒绝。
4. Replicate poll 与 download、task direct/Sora/Veo/MJ 的实际调用边界；SSRF/private/metadata、取消、错误 TLS 及并发 race 回归。旧跨站剥头测试迁为显式 media，保留“B收到但无凭据”断言，并新加 API 的 B 零请求断言。
5. 少量真实 MySQL 官方宿主代表：原任务凭据/固定价、普通查询与交付、未知3xx回执及资金不变；复用原真实 fixture，不把纯客户端测试称为持久化证明。

本地定向/相关包/vet/diffcheck 后交独立审查；主控统一 Linux race、真实 MySQL 与最终 make vet/ci。无 DSN/Windows socket 限制明确报告，skip 不算通过。期间不调用收费接口、不部署生产。本契约不代表完成凭据接管、完整网络 fence 或500并发验收。
