## 4. 同一 FilterSpec，四个入口

组织列表 `/api/usage`、后台列表 `/api/admin/invocations`；组织导出 `/api/usage/export`、后台导出 `/api/admin/invocations/export`。全部显式 `filter_version=1`，并使用固定 `source=invocation_log`、`time_basis=recorded_at`、`timezone`、成对时间边界与 `display_currency`。列表追加 page/page_size；导出绝不能包含二者。API 参数只用 URLSearchParams.set，避免重复。

`draft` 是编辑表单；`applied` 是点击“查询”时复制并冻结的规范化条件。chips、合计、分页和导出只指向 applied，不把正在编辑但未提交的字段当已查询。显式查询重置页码为 1 并只发送一次；重置一次提交默认条件；刷新保持 applied/page，快捷相对日期只在重新应用时重算，不能午夜翻页时漂移到另一集合。下载按钮标“导出已应用条件”；draft 未提交时可提示有未应用变更，不导出草稿。

序列化规则：

- 普通端类型与运行时白名单都禁止 org_id/channel_id，绝不信任路由 query 透传。后台字段可选，空值省略；ID 保持十进制字符串，不用 v-model.number 或 Number 转换。后端现有 row ID 为 JSON number 的边界不在本批改变；不得声称能恢复已经被 JSON 解析舍入的任意 uint64。
- 结果筛选用互斥联合：all 不传 result/status；success/非成功传 result；精确状态传 status（success/upstream_error/no_channel/insufficient_balance）。绝不传 status=failed，也不同时传 result 与 status。卡片名称为“非成功”，不会把缺失在途状态臆造为生成失败。
- 模态使用 tagged 值：all→不传；历史未记录→显式 `modality=`；具体值→chat/embeddings/rerank/image/audio_speech/audio_transcription/realtime/video/music（已核对 invocation.go 常量，STT 对外值为 audio_transcription）。不能以 `if(value)` 丢掉历史空筛选。
- 流式为 all/true/false，false 必须显式传 false。模型、请求 ID 去除用户输入两侧空白后校验允许长度；不做本地子串筛选；api_key_id 可用辅助名称与 ID，但 API 只传 ID。
- filter_hash 是服务端授权集合的身份，不含分页/币种；只用于显示和列表导出口径核对，绝不能代替完整客户端上下文 key。
- 本轮只白名单持久化非敏感范围/模态/模型/分页等 URL 字段；不写 token、Authorization、root token、payload、自由错误。request_id/ID 若入 URL 须明确评估隐私，默认不持久化。解析 URL 不能变成绕过上述白名单的通用 query 转发。

## 5. 时间、金额与精确用量

默认显式 UTC，自然日筛选和表格时间都显示时区，不依赖浏览器本地时区。可用受控 IANA 选项；首批至少 UTC/Asia/Shanghai，DST 测试通过相同纯函数覆盖 America/New_York。日期控件只保存 YYYY-MM-DD。

- 7 天为所选时区今日前 6 天到明日；30 天为前 29 天到明日；本月为月初到明日；上月为上月初到本月初。
- 自定义 UI 的结束日明确“含当天”，仅在提交边界把日期加一个日历日，再把日期形式 since/until 交给后端按 IANA 时区转 UTC；不能给完整 ISO until 再加一天。采用日期分量运算，不对所选时区瞬间粗暴 +86400000（DST）。
- 开始/结束必须成对、合法、先后正确、最长 90 自然日；编辑未完成时不发请求。90 天由日历日期跨度校验，最终以后端严格校验为准；服务端 normalized_filters 的 UTC 半开边界在详情可查看。
- 响应是原子 bundle：items、totals、query、page/page_size/total 一起替换。费用合计显示 totals.cost_display 原字符串；行费用以 cost_usd × 本响应 query.display_money.cny_per_usd 精确换算。抽屉捕获同一 bundle 的 FX。不得使用页面当前 currency store 的新 rate 改算旧行。
- 全站 currency store 仅决定下一次请求的 display_currency；币种变化触发新查询并丢弃旧币种响应。汇率 store 后续变化不能静默改已有结果；主动刷新才获得新快照。rate_source 为 default_missing/default_empty 时给可读来源提示，不能冒充管理员设置值。
- Token 只用 usage_exact 和 totals 的十进制字符串；BigInt 计算输入+输出总量与千分位，禁止 Number/parseInt/i18n n() 先转换。缓存/推理展示子项，不再次相加。缺 usage_exact 或非法字符串为契约不可用，不能降级到可能失真的旧 numeric 字段。
- 当前 usage_presence=legacy_not_distinguishable、missing_usage_count=null：界面显示“历史记录未区分未上报与实际 0”，零可显示“0（记录值）”，不能把 0 或 falsey 猜成缺失，也不能显示缺失计数 0。不承诺原计划的真实 0/未知区分已完成。
- 微额保留精确文本/可复制完整值；使用既有 formatNativeMoney 的非零阈值显示，不能把微小费用显示为实际 0。合计来自服务端先原币求和再换算，不求和已舍入行显示值。

## 6. 请求与权限竞态：必须作为首批验收主线

每个面板建立 contextEpoch 与 listSeq/metaSeq/exportSeq。捕获上下文至少包含 scope(org/admin)、auth.token/session身份、orgId、role、adminToken 的内存 revision/当前值、面板激活状态、appliedFilterRevision、page/pageSize、请求币种。token 原值只作内存比较，不写 URL/日志/缓存 key。adminToken 当前 sessionStorage API 不响应式，需 set/clear 主动发 revision，并在所有结果发布点额外对比实际 get() 值。

任何 session/token/org/role/root-token/页面激活变化：先递增 epoch、abort 列表/字典/导出，关闭抽屉并立即清空 rows/totals/metadata/下载记录/错误。新上下文合法后再查询。角色降为普通 admin 时不能继续显示旧平台明细；logout/login 同 org 也必须隔离。管理员有 root token 时只启用本来后端已兼容的日志路径；普通 admin 无 root 不能加载日志、不能打开详情，强行 URL 也不请求该面板。root token 非空不是授权成功，401/403 清当前面板并提示，不能回退组织或无版本接口。

列表/字典每次新请求各 abort 上次并捕获 seq；await 完成后成功、catch、finally 都复核完整 epoch/seq/上下文。过期失败不能清新结果、写错误、改 loading、登出新会话。AbortError 为用户操作/上下文取消时不报网络失败。更换筛选清旧结果或明确显示为旧条件 stale，不允许“新 chips + 旧合计”。建议首批清 bundle 后 skeleton，降低误认风险。

分页仅更新 listSeq，成功 rows+totals 同时接受。每页 live，正常数据未变时合计不变；并发写入变化时展示新 as_of，不承诺固定集合。X–Y 使用 `(page-1)*size+1` 至起点+行数-1；空页为 0 条并保留 total，可提供返回最后有效页，最多一次明确重查，不能无限自动请求。

字典独立 loading/error，不阻塞日志金额；逐次复核身份 epoch，跨组织旧 Key 名称不能泄入新组织。详情仅从已接受 bundle 按 request_id/记录ID选取，进入新查询/身份变化就关闭；关闭保留已应用筛选/页码/滚动位置。

## 7. 下载闭环与资源边界

下载捕获 applied、当前授权上下文、币种与 exportSeq；列表与导出均使用同一 FilterSpec builder，唯有分页字段不同。一个面板同时间只允许一次导出；相同主体跨组件的后端429仍正常处理。身份/币种/应用条件变化、切出面板、卸载、点击取消均 AbortController.abort()。第一页/第二页切换不改变导出集合，可允许当前下载继续，但成功提示必须仍属于相同 applied/币种/身份。

下载 transport 复用 api.ts 的凭据规则，携带 root header 的 admin 请求保持后端既有优先级；不在组件手写认证逻辑。请求使用 no-store。检查 HTTP 成功、CSV Content-Type、受控 Content-Disposition、v1响应元数据后才读 blob/创建对象 URL；错误读取安全 JSON 并带 request ID，不能把错误文件命名.csv。后端3秒预算仍有效，浏览器可设略长网络兜底（如10秒），不改变业务期限声明。

为防异常代理返回巨量内容，下载响应体可用 stream reader 累计上限8MiB（每块读取受 signal 控制），超限 cancel；无流浏览器需先检查Content-Length并采用已定有限 fallback，实施时定稿，不用无界read后才检查。完整 body 后再次复核 epoch/身份/applied/币种，再创建 URL并触发下载；发生 stale/abort 绝不点击 anchor。finally 撤销已创建的对象 URL并移除 anchor，不在 revoked URL上保留“下载成功”。浏览器一旦实际启动保存无法追撤，因此最后校验必须紧邻点击。

成功显示“按当前条件导出 N 条”，注明 CSV 是导出请求时的新观察，展示导出自身 as_of/currency/rate，不把 CSV 元数据覆写当前列表。5000上限无截断：422 export_limit_exceeded 或 export_size_exceeded 提示缩小时间/条件，不自动拆批、不导当前页假装全部。429按 Retry-After 提示稍后重试，无自动密集重试；503不显示空 CSV或金额0。0记录允许只表头文件，其合计来自响应头。

## 8. 页面工作区与验收

紧凑标题显示“当前组织/全平台”、刷新、导出和当前币种；不新增第二套币种偏好。统计条为请求数、成功/非成功、输入/输出Token、日志记录金额；高级项为缓存/推理和口径说明。筛选显式查询/重置，已应用chips；模型/Key可精确输入。管理员增加组织/渠道ID筛选，名称辅助仅在已有授权数据可用时使用，不逐行请求。不显示未实现分组历史、正文按钮或供应商成本。

复用 DetailDrawer，标题/请求ID按钮可键盘操作；支持Esc、Tab焦点圈定、返回焦点；长ID可复制并换行。普通详情不渲染org/channel/provider/payload key，即使测试故意塞这些字段也不显示；后台只用v1已列字段，删除现有payload_object_key显示分支。异步错误/空/加载分别有文案与aria状态，不能全变“暂无数据”。

独立验证矩阵：

1. 复用后端237条声明oracle（120/80/37组织、180成功/57非成功），前端测试数据从固定声明读取/生成，不调用生产筛选求期望。20/50/100、末页/空页与13种组合筛选；页面合计/导出元数据按同一声明核对，不通过本页求和冒充全量。
2. 精度正控：>2^53逐行Token、两行SUM>MaxInt64、0.00000001 USD、CNY6.65；USD/CNY切换后旧响应不能覆盖；服务端FX在两请求间改变时旧bundle和抽屉不重算，新CSV按其自身快照。
3. 日期：UTC、Asia/Shanghai、DST跨越；7/30天、月/上月、同日起止包含一天、90/91天、空一端、ISO边界不得二次加日；失败与精确状态互斥、is_stream=false、历史modality空与all可区分。
4. 控制Promise完成顺序，真实watch/effectScope验证：A组织→B；同org新token；role降级；root token置换/清空；旧401；快速筛选/分页/币种/Tab切换；meta晚到；catch/finally晚到；卸载。每类都断言 DOM/状态不回填、abort执行，不能只测生成query字符串。
5. 下载：正确Bearer/root header；无page；5000/5001、0行、422/429/503、非法Content-Type/超限响应、body读取中取消、完成后点击前上下文变化；断言只在当前成功上下文创建/点击URL，且撤销URL释放。
6. 浏览器实际挂载普通用户、superadmin、root-token三种路径；普通admin拒绝平台视图；两入口同筛选结果；右侧抽屉；文件实际下载核对币种/Token；1920/1440/1280/768/390px、明暗主题、200%缩放、键盘。控制器测试不能代替真实布局验收，截图只用合成数据。

构建门禁：新增node:test接入现有脚本、typecheck、check:money、check:i18n、build 与 make ci-all；后端冻结API回归保持。先局部共享逻辑和测试，再接两页面；浏览器看到的本地进程必须是本次树的构建/依赖，记录实际URL/commit及启动方式，避免旧进程造成“刷新没变化”。不得以237正确性宣称500并发。

## 9. 建议实施次序与主控决策点

A：主控先将本草案纳入正式架构/契约并固定root-token日志入口、时区选择范围、下载体积读取兼容策略。B：共享Filter/DTO/transport/epoch及有延迟的行为测试。C：抽取通用面板、接普通和管理入口并移除重复旧watch。D：精确金额/Token、CSV、角色/竞态回归；E：本地当前进程浏览器验收→make ci-all→独立审查→PR/CI。可以把纯函数与面板/浏览器验收分线，但 api.ts/auth上下文相关变更须单一owner。

现有主要风险是旧401误登出、root-token非响应式、默认FX重算、日期旧单边参数、历史空模态丢失、管理旧load晚到及Blob晚下载。这些应在首批完成，不能留为UI美化之后。A2a真实验收/合并前不接入生产，不通过旧接口兜底掩盖后端版本未部署。


## 10. 主控已冻结的实施选择

- 日志入口保留后台已经支持的root token兼容，前端仅按superadmin或当前root token提供访问尝试，最终以后端授权为准。不得扩散到其它后台Tab；401/403明确失败，不退旧接口。
- 首批时区选择UTC、Asia/Shanghai、America/New_York，默认UTC；日期边界由纯日历算法生成日期字符串，后端IANA解析。后续扩展选项不影响契约。
- CSV下载使用有界ReadableStream，8MiB；无可读body或浏览器不支持stream时明确失败，不以先无限blob再检查作为兼容兜底。空结果仍有CSV表头，不能混同空网络body。
- 初始不新增筛选URL持久化，既有Tab路由保留；避免用户输入的请求ID落入地址历史。draft/applied与条件chips保持单页闭环。
- 开发顺序先纯函数/DTO和transport，再controller，再共享面板及两入口，最后独立受控异步测试、浏览器真实挂载/导出和make ci-all。controller及全局api最小变更必须单一owner；不能把测试源码字符串检查冒充实际Vue行为。

## 11. 实现收敛与独立验证范围

初版没有新增字典端点或异步字典加载，因此不存在metaSeq实际请求；已实现list/export序列与完整身份epoch，不能把草案中的字典竞态写成已验收功能。session到期继续依赖既有401路径及身份store变化，本批没有全站空闲到期计时器，不能宣称静置页面会在JWT到期瞬间主动清屏。

全部Token使用十进制字符串与BigInt，普通DTO白名单不保留平台字段；下载只接受有界UTF-8 ReadableStream及固定列头，无body或非法编码明确失败，无无限blob回退。api.ts旧401仅能清理其捕获的同一会话，旧请求的成功/失败/finally和下载点击前均校验当前上下文。根Token变动通过revision响应并在发布点再读实际值，原始sessionStorage变动也不能让旧finally留下永久loading。
