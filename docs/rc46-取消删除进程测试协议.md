## 1. 进程启动与环境

直接启动测试二进制，不经 shell 或 test2json 包裹：

```text
Popen([binary, "-test.run=^TestMySQLMutationBinaryHandoffProcess$", "-test.v", "-test.count=1", "-test.timeout=12m"],
      stdin=PIPE, stdout=PIPE, stderr=PIPE, env=child_allowlist)
```

runner 的超时与真实 PID 是主权威；test.timeout 是最后一道有限保护。stdout 原字节保存并另外送 `go tool test2json -p <Ca或P> -t` 的 stdin，不能杀转换器来冒充杀测试进程。stderr 另存。每个正常退出进程必须同时 exit=0、实际 RUN/PASS、无 SKIP/FAIL 和协议 stopped；已验证的 SIGKILL 屏障阶段单列 expected_crash，不伪造 PASS。

仅传以下测试变量，未知 `A2C_*` 拒绝。宿主环境只保留必要 PATH、HOME、TMPDIR、TZ=UTC、LANG=C.UTF-8；移除代理、所有外部 LAIAI_*/ARK_TEST_*、GOFLAGS/GOWORK 等。DSN 和密钥不进 argv、事件或报告。

## 2. stdin 严格命令

每行一个 UTF-8 JSON 对象，最多4096字节，无 BOM/重复字段/未知字段/null；EOF 只有已 stop 时正常，其他情况失败。公共字段必须是 `protocol,run_id,case_id,instance,cmd_id,command`，协议/run/case/instance 必须逐字匹配 env。cmd_id 从1开始严格递增的正整数；拒绝重发/跳号，不自动幂等重放命令。

```json
{"protocol":"a2c-process-v1","run_id":"0123456789abcdef","case_id":"N3-cancel-Ca","instance":"sender-p","cmd_id":1,"command":"run_once","barrier":"inbox_durable_before_apply"}
```

| command | 附加字段 | 允许模式及语义 |
| --- | --- | --- |
| `seed` | 无 | seed，仅一次：建立配置/入金/真实 Key，通过 Create→ProcessOnce 创建已绑定 queued；delete 再实际 GET succeeded 结算；最后公开 Cancel/Delete 提交 pending。写 seed.json，发 seeded/pending_intent，随后完成命令。不得立即派发该动作 |
| `run_once` | `barrier` 必填枚举 | worker，调用一次真实 Service.ProcessOnce；barrier=none/start/registered_before_http/inbox_durable_before_apply/legacy_claim_before_http/legacy_receipt_durable。只允许一个活动周期，不能同时启动下一周期 |
| `release_barrier` | `barrier`,`owner_cmd_id` | worker，只能释放当前已报告的 barrier，且 owner_cmd_id 是活动 run_once。只解除测试等待，不写数据库。重复/错误屏障失败 |
| `advance_clock` | `to` UTC 毫秒时间 | worker/inspect 的 logical 时钟；只在无活动周期时，严格不后退。wall 拒绝。只更新 Service.Now 依赖的原子时间，不修改 lease/due/状态；inspect 仅记录观察逻辑时间 |
| `inspect` | `label` | inspect，label=`[a-z][a-z0-9_-]{0,47}`；在独立只读 RR 事务检查，写独占 snapshots/<instance>-<cmd_id>-<label>.json，并输出 inspected。调用不做消费或修复 |
| `purge_expired` | 无 | worker，仅 R2 两例，空闲时调用真实 Evidence.PurgeExpired(ctx,1000)；必须定位并验证本动作 input 前后变化，不能以 purge count>0 冒充目标已清理 |
| `stop` | 无 | 任意模式，仅空闲；有界关闭自己连接，输出 stopped、正常返回测试。活动周期中 stop 拒绝，不偷偷取消业务或省略证据 |

命令成功均发 `command_done`。run_once 可先发 run_started，然后控制读取循环继续收 release_barrier；业务 goroutine 和控制循环全部 join 后才能正常返回。release_barrier 有自己的 command_done，原 run_once 的 command_done 只能在 ProcessOnce 实际返回后发出。任意失败输出固定 error 事件并 FAIL，不继续下一命令；不得回显未知输入、SQL、原错误。

默认单个业务周期60秒，barrier等待最长60秒，inspect/verifier5秒，启动15秒。墙钟240秒等待发生在 runner，空闲子进程可以保持超过60秒；不能因 idle 自动 FAIL。控制命令自己的有限期限不计入被明确暂停的屏障时长。SIGKILL 的目标必须仍在指定屏障中。

## 3. stdout 事件

所有自定义行以 `A2C_EVENT ` 开头，后接单行 JSON；公共字段固定：

```json
{"protocol":"a2c-process-v1","run_id":"0123456789abcdef","case_id":"N3-cancel-Ca","instance":"sender-p","role":"Pon","mode":"worker","pid":12345,"seq":1,"cmd_id":0,"event":"ready","data":{}}
```

seq 从1递增，事件写出用单一锁，单行最多65536字节；pid=os.Getpid。cmd_id=0 只用于启动 ready/启动 error。所有数据库 uint64 ID 和 version 以十进制字符串编码，计数/seq/PID 为有界 JSON 整数；所有金额/Token 精确十进制字符串，时间 UTC 毫秒或 null。

事件名称及 data 唯一形式：

- `ready`：`source_sha,clock_mode,clock,db_time,create_inbox,mutation_field_present,mutation_inbox`。Ca mutation_inbox=null。worker/inspect 已读取 seed.json，含 `org_id,task_id,operation_id`；seed 启动尚无这三项。
- `seeded`：`seed_file:"seed.json",seed_sha256,org_id,key_id,task_id,operation_id,action,clock,upstream_id,baseline_financial_sha256`。
- `pending_intent`：`org_id,task_id,operation_id,action,operation_status:"pending",mutation_attempt_count:0,receipt_count:0`。必须已有独立 DB 正控，不仅 API 返回。
- `run_started`：`barrier,clock`。
- `barrier_reached`：`barrier,owner_cmd_id,verification_file,verification_sha256,clock,db_time`。start 的 verifier 文件只证实该 PID 已进入周期前屏障；其他屏障必须有真实提交后的独立连接事实。
- `clock_advanced`：`previous,to,db_time`。
- `purged`：`input_payload_ref,purged_count,before_identity_sha256,after_identity_sha256,wrapped_key_present:false,nonce_present:false,staging_count:0,capture_status:"expired"`。
- `inspected`：`snapshot_file,snapshot_sha256`（相对 case 目录路径），不在 stdout 复制整个快照。
- `command_done`：`command`；run_once 另含 `clock,db_time,process_once_returned:true`。ProcessOnce 本身可能记录单条业务错误但返回nil，runner仍必须检查真实DB后置条件，不以此事件替代成功判定。
- `stopped`：`completed_commands`；随后测试真正 PASS。
- `error`：`code`，枚举 startup_invalid/config_invalid/database_unavailable/invalid_command/business_failed/barrier_failed/barrier_timeout/inspect_failed/invariant_failed/cleanup_failed。无 message/raw cause/SQL/DSN。

runner 严格验证 run/case/instance/role/mode/PID 和seq、cmd关联，拒绝未知事件/字段、重复 ready/barrier；非前缀 Go test 输出单独保存而不解析成自定义事件。事件不是测试通过证据。

## 4. seed 与 inspect 工件

`seed.json` 独占0600创建，固定 protocol/run_id/case_id/action、合成org/key/task/operation/providerScope/channel/hold ID、upstream_id、creation_role、history_enabled、initial_time、seed_finished_clock、mutation_kind、公开create的固定 oracle 输入、财务基线。没有 plaintext Key/token、密文、签名 URL、prompt 或 DSN。worker必须核对case身份，并独立读取真实DB，不能把seed快照当当前状态。

固定 seed oracle：信用入金100 USD；720p 16:9、1280×720、24fps、duration=5、risk=1、倍率=1；单价8 USD/1M，供应商46 CNY/1M，FX=0.14 USD/CNY。无输入视频与最低用量。预估108000 tokens、hold=0.86400000 USD、供应商预留4.96800000 CNY；GET succeeded明确completion_tokens=100/total_tokens=100，实扣0.00080000 USD、供应商0.00460000 CNY、未用冻结释放0.86320000 USD。以上由独立十进制算式核对，不读最终余额反推。若实际既有计量契约不同，立即报告失败，不改 oracle/状态迎合结果。

inspect 快照固定顶层 `protocol,run_id,case_id,instance,label,source_sha,clock,db_time,ids,task,operation,mutation_attempt,inbox,action_input,legacy,finance,fingerprints,audits`：

| 区块 | 字段/含义 |
| --- | --- |
| ids | org_id/key_id/task_id/operation_id/upstream_id/hold_id |
| task | status,billing_state,deleted_at,next_poll_at,upstream_id |
| operation | status,version,attempt_id,lease_until,error_code,receipt_ref,receipt_applied_at；只读取固定safe error code |
| mutation_attempt | count；唯一行时 id,operation_claim_version,storage_protocol,action,input_schema,observation_schema,delivery_schema,target,input_payload_ref,registered_at,runtime_descriptor_hash,action_descriptor_hash；完整四元组检查在 harness 中执行 |
| inbox | count；唯一行时 receipt_id,attempt_id,response_payload_ref,outcome,http_status,application_state,application_error_code,next_attempt_at,applied_at,applied_event_id,response_received_count；evidence_hmac仅给SHA256摘要 |
| action_input | 若无登记为null；否则payload_ref,capture_status,expires_at,wrapped_key_present,nonce_present,staging_count,identity_sha256；identity排除可变清理列，永不读取明文 |
| legacy | receipt_present,receipt_ref,receipt_applied_at,attempt_count；不暴露正文 |
| finance | credit_usd,available_usd,frozen_usd,hold_usd,captured_usd,released_usd,hold_state,capture_journal_count,release_movement_count,billing_entry_count,quota_reservation_count,quota_bucket_count,ledger_drift_count；解冻不是journal，seed启用合法ledger.EnableActivityTracking后从unfreeze movement计数 |
| fingerprints | accounts/holds/journals/ledger_movements/ledger_operations/ledger_events/billing_entries/quota_reservations/quota_buckets/key_usage/financial_all/action_application_events 各sha256；按精确org/task/key范围、稳定排序和白名单列。全表全task事件数量不用于动作幂等 |
| audits | execution_read_count（按本task及准确action input）、response_capture_status,response_staging_count |

可在初版实现时补齐表列具体投影，但上述顶层、字段语义及命令事件不变；新增字段须两边同时确认。不存在的行用null和count0，不用伪造零值有效对象。每次inspect同一RR事务内完成，ledger.CheckDrift只读执行；普通GET产生的query证据不能误计动作receipt。快照不包含任意完整gorm模型。

## 5. 屏障挂点与状态机

run_once.barrier 是该周期一次性屏障；在seed阶段不可安装动作屏障。

- `none`：无暂停。
- `start`：run_started之后、调用ProcessOnce之前发barrier_reached；M3必须先收齐两个PID的事件再分别release，结果必须实际争同一pending操作。
- `registered_before_http`：P主事务真实Commit成功，第三未装饰连接核验目标op=in_flight、schema2 EA+input+staging已提交、inbox0后暂停。匹配org+op+kind，不拦create/query。
- `legacy_claim_before_http`：Ca主事务真实Commit成功，核验目标op=in_flight/attempt/lease已持久且没有mutation EA后暂停，供M2。
- `inbox_durable_before_apply`：专池真实Commit成功，核验唯一receipt+payload元数据+application.pending+response_received已提交、原op尚未应用后暂停。
- `legacy_receipt_durable`：Ca主池persistResponse真实Commit成功，核验op.receipt_ref/outcome和Attempt/Invocation已提交、receipt_applied_at=NULL、mutation EA0后暂停。

Commit装饰器必须真实Commit→独立查询→原样返回；暂停发生在返回之前。不用AddError/伪造EOF/强制回滚/事务内回调冒充“提交后”；退出屏障只释放channel。独立verifier使用短ctx与独立未装饰pool，不触发递归屏障，也不持锁等待runner。

`delete_seen_no_response` 属于Mock控制屏障，不是harness barrier枚举：runner令mock hold DELETE，wait状态确认计数1，再独立inspect证明EA已登记/inbox0，然后SIGKILL真实worker PID；进程退出后才给mock drop_waiting 释放连接。

`pending_intent` 是seed完成事件；`applied` 不新增虚拟挂点，以run_once完成后inspect实际证据判定。

## 6. 外部 Mock HTTP 协议（runner 拥有）

每case一个独立127.0.0.1端口，计数从0开始且本case永不reset。Mock可在runner线程中，但不能在业务worker进程中。POST/GET/DELETE都先计数后响应；保留每请求递增request_seq、instance、method、safe outcome、是否等待/响应；不记Authorization、body或完整URL。

业务transport先核验原请求：scheme=https；host精确ark.cn-beijing.volces.com；无userinfo/fragment/query/端口；路径精确 `/api/v3/contents/generations/tasks`（POST）或加唯一固定upstream_id（GET/DELETE）。Authorization必须等于合成token，POST body有界且使用真实adapter产物。然后克隆请求仅把scheme/host改为本case mock；添加X-A2C-Run/X-A2C-Case/X-A2C-Instance标识，清理任何传入同名头。transport底层Proxy=nil、DialContext只许唯一loopback IP:port，拒绝redirect，原host校验失败零拨号；绝不访问官方。model配置仍是正式HTTPS Ark URL，AllowTestEndpoint保持false。

Mock业务响应固定：

| 请求/模式 | 返回 |
| --- | --- |
| POST | 200 JSON `{"id":"<固定upstream_id>"}` |
| GET queued | 200 JSON id + status=queued |
| GET succeeded | 200 JSON id + status=succeeded + usage completion_tokens=100,total_tokens=100；无artifact URL |
| GET cancelled | 200 JSON id + status=cancelled；无usage，seed已明确cancelled为no-charge |
| DELETE ack204 | 204空body |
| DELETE not_found404 | 404 JSON `{"error":{"code":"TaskNotFound","message":"synthetic missing"}}` |
| DELETE upstream502 | 502 JSON固定合成错误 |
| DELETE eof | 接受并计数后直接关闭socket，不发送HTTP状态行；不得抛mock客户端异常代替真实EOF |
| DELETE hold | 计数并挂起，待控制release；request_seq可作为精确等待ID |

所有JSON Content-Type=application/json、固定安全X-Request-Id合成值；body必须完整，404不得人为标truncated/credential-reflection。

Mock控制接口只允许runner，独立合成控制token（不传worker），header `Authorization: Bearer <control>`。控制读取/写入不计业务请求。

- `GET /__a2c/status` → `{protocol,run_id,case_id,seq,post,get,delete,by_instance,pending_deletes,requests}`；by_instance含同三计数；requests最多100项，超限立即整例失败；pending_deletes为request_seq数组。
- `POST /__a2c/control`，严格JSON `{"command":"set","query_sequence":["queued"],"delete_response":"hold"}`。query_sequence长度1..3，逐GET消耗、最后一项重复；不重置已发生计数。该控制用于seed delete的queued→succeeded和Q1明确GET终态；普通场景seed后重设queued。
- 同端点 `{"command":"release_delete","request_seq":3,"response":"ack204"}`：仅一次释放准确等待请求，response仅ack204/not_found404/upstream502/eof。
- 同端点 `{"command":"drop_waiting","request_seq":3}`：仅在worker被确认SIGKILL退出后使用，关闭对应等待socket，不伪造响应。
- 控制成功200 JSON `{ok:true}`；非法控制409固定码。Mock stderr仅安全固定诊断，线程/等待结束由runner有界join。

runner等待DELETE可每100ms读status且最大60s；此轮询只loopback，不能拿harness一条stdout当mock证据。Mock回执和实际DB快照需同时满足场景屏障才允许杀进程。

## 7. 时间与首个可执行交接

logical时钟统一从seed_finished_clock起。不同进程均advance到同一明确时间；只在空闲推进。跨lease读实际operation.lease_until再+1ms；跨query读next_poll_at；R2跨准确input.expires_at。不得UPDATE数据库时间列。wall场景Now=time.Now，advance_clock必失败。Q1的application.next_attempt_at是DB时钟，runner通过inspect.db_time真实等待到due，不靠Service.Now。

首个集成目标 `N3-cancel-Ca`：

1. runner建库迁移，mock设queued/ack204；Pon seed启动→seed→取seed.json→stop真正PASS。
2. Pon worker启动，run_once(inbox_durable_before_apply)；收真实barrier和Mock DELETE=1；inspect核验application.pending及active lease；SIGKILL准确PID并核验-9。
