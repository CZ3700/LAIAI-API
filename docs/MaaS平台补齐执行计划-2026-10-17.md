# MaaS 平台补齐执行计划

基线：`22a06a1446e9fb546c93c1b7518c40fab17aa63b`（PR #19，尚未合并）。依据用户提供的《弦序聚合MaaS平台_全站功能调研与实施方案_LAIAI.md》全文，以及火山方舟视频生成模型价格快查表。

## 已确认决策

1. 完整收录可核验的官方参考价和最低 Token 数据；保留现有客户售价，新增组合暂不发布。
2. 所有“详情”点击统一从右侧展开；不将创建、编辑、认证、支付、删除确认误改成只读详情。
3. 分阶段分支、测试、GitHub PR。基于 PR #19 继续增量开发，不改根工作区已有改动，不自动合并或发布生产。
4. 保留 `/v1/video`、平台任务 ID、组织权限、现有钱包和账本。参考站接口不能替代火山官方协议。

## 阶段与并行边界

### S1 官方目录与详情一致性（本轮执行）

- 总控：来源采集、数据核验、架构及计划、集成、验收和 PR。
- 价格线 `codex/ark-official-price-catalog`：只读官方目录、单位/证据检查、后台浏览；售价和发布保持原样。
- 详情线 `codex/maas-detail-drawers`：共享抽屉、模型/资金/素材/管理员/价格历史等已有详情。
- 日志线：通用日志、Seedance 日志、两个操练场详情；与详情线按文件隔离，保留鉴权和异步清理。
- 集成线 `codex/maas-console-completion`：合并已验证阶段、补交付记录、部署本地可用版本。

来源目录覆盖 2.5 价格与最低量、2.0 价格与最低量、1.5、1.0 六张表。每张表记录完整行数、原始列、来源链接、精确/舍入语义及 SHA-256。采集未完成不得标为完整；缺失数据不猜值。目录导入不写 pricing publication，不改变能力开关、预算和现有配置版本。

官网将最低 Token 表明确称为估算值；目录标注 `estimated`，不导入收费规则。表中的示例金额是舍入展示值，不能反算最低 Token 或作为额外最低金额扣费。一个表包含多个型号筛选视图时逐视图保存原始文件和来源，不能将首视图误报为整系列完整。

验收：所有已有详情入口右侧展开；长 JSON/媒体可滚动；Esc、Tab、焦点恢复、窄屏可用；组织切换/关闭后旧异步结果不重开；只有原有权限可读正文；开详情无付费调用。运行 Go vet、全量测试/构建、迁移 lint、Web 类型与构建，最后本地浏览器验收。

### S2 项目与权限基础

先定义客户 Project、默认项目兼容策略、成员/角色授权及迁移；再串联 Key、任务、素材、日志、资金归集与查询范围。所有 repository 强制 org/project 约束。跨租户、项目撤权、后台任务继续结算、旧任务读取是出口测试。单独 PR，不挤入 UI 改造。

### S3 模型开通与身份强化

在项目/组织权限基础上，增加组织模型申请、审批、暂停和原因审计；再做 Key 更新/轮换、会话版本与撤销。网关 admission 与控制台展示共用状态，不能仅加 UI 开关。

### S4 商业运营增量

工单与站内通知、发票领域、客户 AK/SK、SDK 分别立项交付。发票需先确定开票主体、税务口径与供应商；支付/SMTP/OAuth/HTTPS 回调等外部配置由部署提供。未配置时明确不可用，不填演示成功状态。

后续工作包中的数据库字段、接口及分支名是执行计划，尚未创建迁移或发布端点。每个工作包先补唯一架构事实源和可评审契约，再开发；明确需要外部资料的项在相应阶段取齐，不能用前端占位页宣称完成。

## 发布纪律

每次提交前快门禁、推送前完整门禁；有后端账务/权限改动再跑对应真 MySQL 故障与并发验收。PR 写明依赖、实际测试、模拟与真实验证边界。保持现有客户售价与所有任务快照，数据库无逆向回填或虚造用量。本轮不进行新的付费视频生成。
